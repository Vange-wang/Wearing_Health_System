## 一、评估质量确认

方法论严谨，可信：
- 交错提问控制网络漂移（8 问交错，相对结论有效）
- 生产同款注入（SYSTEM_PROMPT + USER.md）
- 思考机制拆解（首 chunk / 首思考 / 首正文 四组实测）
- 关思考参数对照 5 组（找到两种有效方式，两种无效方式）
- 质量 5 问 + 多轮指代逐条对照；回退机制逐文件核对

## 二、核心结论确认

1. **默认 flash 对语音是负优化**：先输出思考段（135~534 字），正文被拖延，TTFT avg 2320ms（尖峰 6s）vs chat 1100ms——直接换 = 首字劣化，不可接受。✅ 确认
2. **关思考后小幅占优**：`extra_body={'thinking': {'type': 'disabled'}}` 或 `reasoning_effort: 'none'` 有效；avg -123ms、max -682ms（尾部更稳），但均值接近噪声。✅ 确认
3. **质量持平**：人设/兜底/诚实/指代/断句全部保持。✅ 确认
4. **回退零成本**（前提：思考开关做成配置项）。✅ 确认

## 三、对齐建议

1. **不为延迟换**：关思考后仅 -0.1~0.2s，首字延迟大头是 DeepSeek TTFT 本身（已判接近下限），换 flash 不是有效杠杆。
2. **轻量通道保持 deepseek-chat**（默认）：无思考段、简单直接、延迟稳定；flash 要关思考（多一层配置 + 风险）。
3. **换不换 = 成本/尾部稳定决策，Vange 拍板**：需按官方定价核算 flash vs chat 计费（本报告未测计费，不下结论）。
4. **若决定换**：WorkBuddy 实现时把思考关闭做成配置项（`lightweight.disable_thinking: true` 才发送 extra_body），切换/回退 = 改 yaml + 重启，零代码改动。

## 四、技术补充（给 WorkBuddy）

- 关思考两种有效方式（extra_body / reasoning_effort）实测都行，选一种即可，建议 `extra_body={'thinking': {'type': 'disabled'}}`（zcode 推荐）。
- `enable_thinking=False` 无效（仍 71~164 字思考），别用这个。
