**A4 前置验证通过，v0.3 可正式开工（需 Vange 确认后重启 gateway 生效）。**

## 三、中期延迟查证 —— 三条均不支持，方向关闭

| # | 查证项 | 结论 |
|---|---|---|
| 1 | 只注入 memory、跳过 skills/工具的轻量模式 | ❌ 不支持（API server 无 per-request 开关，`tools` 字段仅用于幂等指纹） |
| 2 | agent 预热/复用 | ❌ 无（stateless，每请求新建 AIAgent，2.4s 开销每请求付） |
| 3 | 冷启动预热 | ⚠️ 无 gateway 级预热，仅外部空请求暖机 |

**结论**：中期「轻量直通」依赖 Hermes 侧能力，当前 0.18.2 无此能力，**此方向在当前版本关闭**。2.4s 启动开销是 per-request 固定成本，voice-bridge 侧无法消解。

## 四、中期出路裁决（Hermes 裁决）

WorkBuddy 给出两条出路，裁决如下：

**(a) 提交 Hermes 侧能力需求**（改 api_server.py 暴露 skip_memory / 工具集覆盖 / 轻量 mode）
→ **不阻塞，列为可选后续**。理由：依赖 Hermes 改版周期，且改的是 Vange 常驻服务（微信 gateway），风险与等待成本高。

**(b) 跳长期 RAG（voice-bridge 自建轻量通道）—— 采纳，但先做前置查证**
→ 这是当前唯一能把纯闲聊延迟压回 ~1.5s、且 voice-bridge 侧可控的路径。拆两步：

1. **前置查证（不查清不动工）**：voice-bridge 能否**只读访问** Hermes built-in memory（存储位置 / 格式 / 读取方式）——memory 是否封装在 Hermes 内部、有无外部读取接口，目前未知，需 WorkBuddy 实测。
2. **若可读**：voice-bridge 自建轻量通道 = 读 Hermes memory（只读共享）+ 裸模型直连（DeepSeek）→ 纯闲聊延迟回 ~1.5s；技能保留慢路径（完整 agent + 安抚语）。
3. **若不可读**：停工上报，重新议「记忆共享 vs 延迟」的平衡。

**目标态路由（不变）**：
```
纯闲聊/简单问答 → voice-bridge 轻量通道（读 memory + 裸模型）→ ~1.5s
知识库查询 → voice-bridge RAG + 裸模型 → ~1.5s
需技能/工具 → 完整 Hermes agent（先安抚）→ ~3.5s
```
