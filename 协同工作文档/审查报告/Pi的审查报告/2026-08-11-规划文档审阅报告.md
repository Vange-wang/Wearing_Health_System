## 三、亮点

### 1. Spec 颗粒度极佳

`开发环境验证-spec` 定义了 12 条 IDF 验证项 + 4 条 Arduino 对比项，每条都配了：
- 操作步骤（精确到命令）
- 预期结果
- 通过标准（可量化）

这意味着拿到 BOX-3 硬件后不用动脑，按编号逐条跑就行。这是工程文档的标杆写法。

### 2. 延迟预算有工程 sense

方案第四章和 `语音引擎选型` 都对开口延迟做了逐环节预算：

```
静音判定 0.25s + 上传 0.05s + ASR 0.2~0.3s + LLM 首字 0.4~0.8s + TTS 首句 0.3~0.6s + 回传 0.05s
= 1.2~1.6s（流式化后稳定 1.2~1.4s）
```

不吹"500ms 开口"、也不躺平"3~5s"，而是找到物理上限下的最优解 —— 体现了成熟的工程判断力。

### 3. 可插拔接口设计

ASR/TTS/LLM 三层都定义了抽象接口：
- TTS：Edge-TTS 主力 + piper 离线兜底，失败自动切换
- ASR：sherpa-onnx 主力 + FunASR 备选
- LLM：DeepSeek 直连（后续可换）

后期换引擎只需改实现类，接口层不动。这是从项目第一天就种下的"可维护性基因"。

### 4. 风险诚实

不写"一切顺利"的理想文档：
- ESP-SR 编译报错 → 已知坑：删 `.component_hash` 后重编
- Arduino 路线 → 坦诚"无 BOX-3 board 定义，会陷入底层移植"
- USB-C 不识别、烧录波特率、GitHub 下载慢 → 都有对策

这些"诚实"在出问题时价值最高。

### 5. 双路线对比有说服力

Spec §4.1 的 9 维度对比矩阵（IDF vs Arduino）有理有据，结论水到渠成：

> 主推 ESP-IDF v5.2.1。Arduino 无官方 BOX-3 board 定义，缺少 ES7210/ES8311 codec 驱动，会陷入大量底层移植。

## 四、发现的问题

### 🔴 问题 1：方案与 Spec 存在矛盾

| 维度 | 实现方案 §5.2 | 开发环境验证 Spec §4 |
|------|-------------|-------------------|
| 开发板编译工具 | **arduino-cli** | 强烈论证后结论：**ESP-IDF** |

方案 §5.2 仍写着"编译烧录：arduino-cli（Windows 可装）"。虽然方案 §8.1 已意识到问题、Spec 对比矩阵也彻底否决了 Arduino，但方案正文没有同步更新，会导致读者看到矛盾。

> **建议**：方案 §5.2 改为 ESP-IDF v5.2.1，并交叉引用 Spec 选型结论。

---

### 🟡 问题 2：语音桥 Spec 缺少错误码枚举

当前 §5 错误处理仅覆盖：

| 场景 | 状态码 | 存在？ |
|------|--------|--------|
| 无有效语音 | 400 `no_speech` | ✅ |
| LLM/TTS 上游失败 | 502 `upstream_error` | ✅ |
| 音频格式不合规（非 WAV / 非 16kHz / 非 mono） | — | ❌ 缺失 |
| 音频超过 15 秒上限 | — | ❌ 缺失 |
| DeepSeek API key 未配置 | — | ❌ 缺失 |
| ASR 模型加载失败 | — | ❌ 缺失 |

联调时遇到这些问题只能看日志猜，效率低。

> **建议**：在 Spec §5 补充完整的错误码枚举表，至少覆盖以上 4 个缺失场景。建议编码：
> - `400 bad_audio_format` — 音频格式不合规
> - `413 audio_too_long` — 音频超过 15s
> - `500 config_error` — 配置缺失（如 API key）
> - `503 service_unavailable` — 模型未就绪

---

### 🟡 问题 3：语音桥 Spec 缺少自动化测试要求

Spec §4 写了 `tests/` 目录，但 §9 验收标准仅要求"三句手动测试"。以下场景值得自动化覆盖：

- `GET /api/v1/health` 返回值格式校验
- 空音频文件 → 400 `no_speech`
- TTS 引擎切换逻辑（edge-tts 失败 → piper 接管）
- `X-Timing` 响应头格式正确性

手动测试的问题是"测过一次就不再测"，回归靠运气。

> **建议**：Spec §9 增加至少 4 条自动化冒烟测试要求（pytest），覆盖 health / 空音频 / TTS 兜底 / 计时头，写入 `tests/` 目录。

### 🟡 问题 4：里程碑文档内容偏薄

当前 `里程碑文档/README.md` 只有一张 3 行的状态表：

| 里程碑 | 内容 | 状态 |

| M1 阶段1 电脑端验证 | ... | 未开始 |

缺少：
- **DoD（完成的定义）**：M0 的 12 条验证项全部通过才算完成，但里程碑文档没有列出

> **建议**：每个里程碑补充：
> - 准入条件（前置依赖）
> - DoD 完成标准（可量化的验收清单）
> - 关联 Spec 文档链接
