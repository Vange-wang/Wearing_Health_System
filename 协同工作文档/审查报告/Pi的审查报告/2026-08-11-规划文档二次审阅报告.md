## 修复质量评价

### 问题 1：方案矛盾 — 修复彻底且可追溯

初版 `§5.2` 写 `arduino-cli`，修复后为：

> 编译烧录：ESP-IDF v5.2.1 + idf.py（选型依据见 Spec文档/2026-08-11-开发环境验证-spec-v0.1.md §4，最终以环境验证实测为准）

优点：
- 给出了具体版本号 `v5.2.1`，不是模糊的"用 IDF"
- 交叉引用了 Spec 选型结论，读者可溯源
- 保留了"最终以实测为准"的务实态度

同时 `§8.1` 风险部分保留了 `原写 arduino-cli` 的历史记录。这种"正文更新 + 风险区留痕"的双轨写法很好，避免了"偷偷改掉"的信息丢失。

### 问题 2：错误码枚举 — 完整覆盖

6 个场景全部枚举，且 `400` / `413` / `500` / `502` / `503` 的 HTTP 状态码选择语义正确（校验失败→400，超限→413，配置→500，上游→502，未就绪→503）。每个错误码都有 `detail` 字段预留，比初版建议更完整。

### 问题 3：自动化测试 — 边界清晰

4 条 pytest 测试覆盖了最小冒烟集（health / 空音频 / TTS 兜底 / 计时头），且明确：
- 作为 **dev 依赖**，不混入 `requirements.txt`
- 单独写入 `requirements-dev.txt`
- 不违反 v0.1 阶段边界（`pytest` 不算引入新业务依赖）

这个"开发依赖 vs 运行时依赖"的区分非常专业。

### 问题 4：里程碑 DoD — 可量化验收

三个里程碑现在都有了**可衡量的完成标准**：

| 里程碑 | DoD 节选 |
|--------|----------|
| M0 | V-01~V-12 全部通过，证据与报告落盘指定路径，Hermes 审核 |
| M1 | 联调清单全绿：链路通 / 延迟 1~1.5s / 共用记忆 / 热点验证 |
| M2 | 远程延迟可接受 / 7×24 在线 / 随身热点可用 / 电脑停用不双开 |

每个 DoD 都是**可以数出来过了几条的**，不是"感觉差不多了"这种模糊描述。

### 问题 5：顶层 README — 导航性拉满

新增的 `规划文档/README.md` 包含：
- 阅读顺序（带文件级说明，不是光列文件名）
- 子目录职责表（命名规范）
- 变更纪律（Spec 变更须 Hermes 确认、决策敲定后同步更新）

特别好评的是最后一条变更纪律——它在文档层实现了"谁有权改什么"的治理规则。
