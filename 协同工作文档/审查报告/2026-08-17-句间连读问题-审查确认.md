## 一、查证质量评价

三层排查（LLM 文本 → TTS 帧 → 固件播放）全实测取证，质量高。两个亮点：

1. **波浪号码位 bug 抓得漂亮**：分句集里是 `〜`(U+301C)，LLM 实际输出 `～`(U+FF5E)，码位不同不匹配 → 本应分句处不拆 + 50 字兜底词中腰斩（「那|些」）。这是极隐蔽的字符编码问题，实测样本实锤。
2. **句号为零的实测**（4 问句号 0 次）：直接定位到「情感化人设 ↔ 分句机制」的冲突——人设让 LLM 口语化（逗号/波浪号串联），但分句器只认句级标点，语义边界全部丢失。

## 二、根因确认

1. **主因**：人设提示词下 LLM 几乎不用句号，语义转折靠逗号/波浪号 → 整段一次 TTS 合成 → 转折处只剩 edge 逗号自然停顿 157~306ms → 连读感。
2. **字符 bug**：波浪号码位不匹配 + 50 字兜底词中腰斩。
3. **次因**：无语义分级停顿（话题切换 vs 普通句间统一 300ms）。

## 三、修复批准

| # | 措施 | 裁决 |
|---|---|---|
| 1 | 提示词约束「语义转折必须句号/问号/叹号断开」 | ✅ **批准（治本）**，注意别破坏口语化人设——约束「语义转折用句号」，语气词/波浪号保留 |
| 2 | 分句集补 `～`(U+FF5E) + 评估 `…`/`—` | ✅ **批准（治标）**，一行 + 单测 |
| 3 | 兜底拆分对齐边界（max_chars 在最近逗号断） | ✅ **批准（防腰斩）**，小改 + 单测 |
| 4 | 语义分级停顿（话题切换 ~600ms） | ⏸ **进 Spec 评估**（新需求，中成本，回应「按语义决定稍长间隔」原始诉求） |

**不建议逗号入分句集**的判断合理（拆碎句子、语调断裂、句数暴涨），确认不采纳。

## 四、补充提醒（给 WorkBuddy）

修复 #1 时，在人设提示词里加的是「语义转折/话题切换必须用句号断开，逗号一逗到底」的约束，而不是「强制书面语」——口语化人设（语气词、波浪号连接同一话题内的句子）要保留，否则情感化效果会退步。

验收按 zcode 建议：用「你都能做什么呀」复测，拆出 ≥2 句、拆点落语义边界、无词中腰斩、句间 ≥0.6s、句内逗号连贯。
