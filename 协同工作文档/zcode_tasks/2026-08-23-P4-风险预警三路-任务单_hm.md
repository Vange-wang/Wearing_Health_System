## 实施内容

### 任务 A：微信推送（voice-bridge 侧，zcode）

1. **预警 → 推送**：`GET /api/v1/health/alert` 被 BOX-3 轮询消费的同时（或独立后台），触发微信推送：
   - 命令：`hermes send -t weixin:<chat_id> "健康提醒：您父亲心率 128 持续偏高，建议关注"`（chat_id 配置化，放 config.yaml）；
   - 触发节奏：**仅阈值触发瞬间推一次**（poll_alert 已保证冷却期不重复）——但 poll_alert 是 BOX-3 轮询驱动的，若 BOX-3 不在线轮询不会发生 → **预警推送应在 HealthDataStore.update() 内部检测触发**（连续 3 次 + 冷却），不依赖轮询；
2. **日上限 ≤5 条**（Spec §5.4）：计数器（今日已推 N 条，超 5 不再推，次日重置）；
3. **降级机制**（Spec §5.4）：推送失败/限流 → 记日志 + 留存（后续汇总补报设计留待增强，本期先记日志）；
4. **首字红线**：推送全部后台异步（threading），不进语音首字路径；推送失败不影响对话。

### 任务 B：BOX-3 空闲轮询播报（固件侧，zcode）

1. `voice_agent.c` 空闲任务（无对话进行中）每 **30~60s** `GET /api/v1/health/alert`：
   - 200 + WAV 帧 → 播放（复用现有 TTS 播放链路，播完继续轮询）；
   - 204 → 无预警，继续空闲；
   - 空闲判定：当前无语音对话（语音任务不占用）——预警播报不得打断正在进行的对话；
2. 预警播报文本来自服务端（WAV 即 TTS 合成帧，Spec 方案 A 复用帧协议）。

## 验收（Spec §6 + §5.2/5.3）

1. **触发正确**：连续 3 次超阈值（心率 >100 或 <50、血氧 <95%，夜间心率 <45）→ 触发一次；单次波动不警；
2. **冷却**：触发后 10 分钟不重复推送；
3. **微信推送**：子女微信收到「健康提醒：…」（hermes send 成功，日志可见）；日上限 5 条生效（超过不再推）；
4. **BOX-3 播报**：腕部节点数据超阈值 → BOX-3 空闲轮询到预警 → 语音播报（「小V提醒您，心率 128 有点偏高…」）；
5. **不打断对话**：预警播报与语音对话互不抢占；
6. 回归：62 passed + 真机语音/搜索/记忆无影响。
