## 硬件/数据基础（Hermes 已核查，2026-08-23）

### 电池（SENSOR-01 底座原理图实测）

| 项 | 值 | 结论 |
|---|---|---|
| 电池 | 18650 锂电池（B1/B2 弹片触点） | — |
| 充电芯片 | AP5056（U2，500mA） | — |
| **电量采样** | VBAT → R15(301K)/R16(100K) 分压 → **BAT_MEAS_ADC → GPIO10** | ✅ 采样通道现成 |
| 分压比 | 100K/(301K+100K) ≈ **0.2494** | 4.2V→1.05V / 3.0V→0.75V（ADC 满量程内） |
| **充电状态** | ⚠️ **无 GPIO**——AP5056 CHRG/STDBY 只驱动板载红/绿 LED，不接 ESP32 | **充电判定需方案**（见下） |
| USB 检测 | VBUS 经金手指 A15/B15 到主板 | 主板是否有 GPIO 检测待查（mb 原理图） |

## 分工与前置依赖

### codex 可独立做（纯 UI，无前置）

1. **开机加载动画**：display init 后、状态任务前插入 lv_spinner/动画（参考现有 display init 流程 voice_agent.c:600-620）；
2. **电池图标 UI**：右上角 LVGL 图形（电池框 + 内部电量填充 + 百分比文字；`charging` 布尔为真时叠加闪电图标）——**按"充电=布尔值"接口开发，判定来源不阻塞**；
3. **蓝牙/WiFi 图标**：右上角/顶部状态栏，读 `s_wifi_up` + `ble_central_is_connected()` 布尔刷新；
4. **字幕 label**：屏幕下方 LVGL label，接收文本帧更新——**按"收到文本即显示"接口开发，通道由 zcode 提供**。

### zcode 前置（数据通路，codex 依赖）

1. **电量采样**：GPIO10 ADC 驱动 + 分压 0.2494 换算 + 18650 电压-电量曲线查表 → 输出电量百分比（1-100）；
2. **充电判定方案**（二选一，需先查 mb 原理图确认 VBUS 是否接 GPIO）：
   - 方案 A：主板 VBUS 检测脚（若存在，插线即知充电中）；
   - 方案 B：ADC 电压上升趋势判定（充电时 VBAT 缓慢上升，准但不即时，需 1-2 分钟观察窗口）——无 GPIO 时的兜底；
3. **字幕文本下行通道**（voice-bridge + 固件两端）：
   - 扩帧协议：新增文本帧类型（如 type=TEXT，长度前缀 + UTF-8 文本）；
   - voice-bridge：分句后的文本随音频帧并行下发（独立通道，见红线）；
   - 固件：解析文本帧 → LVGL label 更新（异步，不阻塞音频）；
4. 状态变量汇总接口：电量%/充电布尔/WiFi/BLE 统一暴露（如 `ui_status_get()`），供 codex UI 轮询。

## 首字红线（agent.md 最高铁律，强制）

- **字幕通道不得进入首字路径**：文本帧与音频帧独立排队/独立通道，**禁止"等文本发完再发音频"**；
- 固件字幕刷新不阻塞音频任务（LVGL 异步更新）；
- 字幕帧丢/晚到 → 静默（显示可延迟，声音不能等）；
- **验收**：改造前后 llm_ttft + TTS 首帧对比 ≤ +50ms。

## 验收（解冻后）

1. 开机显示加载动画，无长时间空白；
2. 右上角：电池图形 + 百分比正确（ADC 实测 vs 万用表误差 ≤5%）；充电时显示闪电；
3. 字幕：BOX-3 播报内容逐句显示在下方，与声音同步（±1s 内可接受）；
4. 蓝牙/WiFi 图标随实际状态变化；
5. 首字延迟无劣化（≤+50ms）；
6. 语音链路无回归（62 passed + 真机对话）。
