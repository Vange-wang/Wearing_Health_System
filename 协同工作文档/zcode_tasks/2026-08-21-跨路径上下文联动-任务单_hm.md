# zcode 任务单：跨路径上下文联动修复（"重新说一遍"断裂）

- **下达方**：Hermes（审查）· 2026-08-21 · 真机复现（01:27:15→01:27:33）
- **状态**：待 zcode 实施
- **相关文件**：`voice-bridge/app/router.py`、`app/pipeline.py`、`app/llm.py`

## 问题（真机复现）

```
01:27:15 「我的生日是什么时候」→ route=hermes（慢路径）→ 小V 答出生日
01:27:33 「重新说一遍」      → route=lightweight ❌ → 小V 不知道要干什么
```

**根因（两处叠加）**：

1. **路由误判**：`重新说一遍` 含"说"字 → 命中 `NEW_TOPIC_SIGNALS`（router.py:26-30 含"说"）→ 判为新话题 → 不延续上一轮 → 走 lightweight。但"重新说一遍"是**追问**（指代上一轮回答），非新话题。
2. **跨路径历史断裂**：`LightweightLLM._history`（deque）只记 lightweight 轮次（`_remember` 只在 llm.py:326/368 调用）；上一轮 hermes 慢路径对话**不进 deque** → 即便路由对了，轻量通道也没有上一轮上下文可参照。

## 改动要求

### 1. 路由层（router.py）：追问判定补词 + 修正新话题误伤

- `FOLLOWUP_HINTS` 追加：`"重新", "再说", "重复", "刚才", "一遍", "一次"`；
- 修正 `_is_followup`：`重新说一遍/再说一遍/重复一遍/刚才那个/刚才说的` 这类**明确指代上一轮**的短语，即使含"说"（NEW_TOPIC_SIGNALS）也应判为追问——建议：**FOLLOWUP_HINTS 优先级高于 NEW_TOPIC_SIGNALS**（先查追问词，命中即追问，不再反向判定）；
- 保持：短句（≤10 字）+ 无新话题信号 → 追问的兜底逻辑不变。

### 2. 历史层（llm.py + pipeline.py）：慢路径轮次也进共享 deque

- **方案 A（推荐，改动小）**：`HermesLLM` 增加 `remember_round(user_text, reply)` 方法（或复用 LightweightLLM 的 `_remember`），pipeline 在慢路径回复完成后调用，把 `(user_text, reply)` 写入 deque——deque 改为**两路径共享**（谁回复谁写入）；
- **方案 B（更稳）**：把 deque 历史从 `LightweightLLM` 提升到 `StreamingPipeline` 层（两个 LLM 共用一份会话历史），`_get_messages` 从 pipeline 取历史——改动大，但语义最正；
- 建议先 A：HermesLLM 加 `remember_round`（调 `self._history.append` 或共享一个 history 对象），pipeline 在 hermes 回复完成处调用；
- 注意：deque 上限 8 条（4 轮）不变；TTL 600s 逻辑保持。

### 3. 路由记忆联动（router.py）

- `Router._set_last_route` 已记录上一轮路由（含 hermes）——确认 `_is_followup` 修复后，"重新说一遍"能正确走 `route=hermes`（延续慢路径）或至少 lightweight 但带上下文。
