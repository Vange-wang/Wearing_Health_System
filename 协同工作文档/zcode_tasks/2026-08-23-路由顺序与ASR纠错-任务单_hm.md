# zcode 任务单：路由顺序修正（DATA 优先于祈使词族）+ ASR 血氧误识别兜底

- **下达方**：Hermes（审查）· 2026-08-23 · 真机复现（16:30-16:33）
- **状态**：待 zcode 实施（SERIOUS——语音查询体验核心）
- **相关文件**：`voice-bridge/app/router.py`、`app/pipeline.py`、`app/config.py`

## 问题（真机日志复现）

```
16:31:07 「你再看一下」→ route=hermes (tool keyword: 看一下) ❌ 应指代上一轮数据查询
16:32:15 「血阳是多少」→ route=lightweight ❌（ASR 把血氧听成血阳）
16:32:35 「我现在在学养是多少」→ route=rag ❌
16:33:02 「我的血氧是多少」→ route=data ✅（正确，唯一正常）
```

## 根因

**1. 路由判定顺序错误（主因）**：`tool_keywords`（祈使词族 查一下/看一下/找一下）判定在 **DATA 路由之前**（router.py:112 tool_keywords 循环 → 108-113 DATA）：
- 「你再看一下」命中"看一下" → 走 hermes 慢路径 → 慢路径不理解"再看一下"指代上一轮数据 → **不返回数据**；
- 「帮我查一下血氧」同理：命中"帮我查/查一下" → hermes 慢路径 → 慢路径无健康数据 → 答非所问；
- **正确语义**：DATA 查询（心率/血氧）应优先于祈使词族——用户说"看一下血氧"意图是查数据，不是搜网页。

**2. ASR 血氧误识别（次因）**：血氧 → 血阳/学养/学样/血压（同音/近音），`data_keywords` 只有"血氧"字面 → 不命中 → 走 lightweight/rag → 不报数据。

**3. 慢路径对"指代追问"不返回结果**：ISSUE-0013（跨路径上下文联动）未修之前，慢路径收到「你再看一下」无上下文 → 回复与数据无关或空转。

## 修复要求

### 1. 路由顺序：DATA 提到 tool_keywords 之前（主修复）

`router.py` 判定顺序改为：

```
① 能力询问判定（CAN do）
② 礼貌白名单（POLITE）
③ DATA 路由（心率/血氧关键词）——提前到祈使词族之前
④ tool_keywords（祈使词族/搜索词）→ hermes
⑤ RAG → 会话记忆 → lightweight
```

- 「我的心率跟血氧是多少」→ DATA（含"心率"即命中，模板直答会同时报心率+血氧——pipeline 已支持多字段）；
- 「你再看一下」→ DATA 关键词不命中 → 落到会话记忆分支（上轮 DATA + 指代追问 → 延续 DATA？**需要新增**：`_last_route == DATA` + `_is_followup` → 回 DATA 重新报数）——**这是"再看一下血氧"能正确返回数据的关键**；
- 「帮我查一下血氧」→ DATA（血氧命中）→ 模板直答。

### 2. ASR 血氧近音词兜底（config 层）

- `data_keywords` 追加近音词：`血阳`、`学养`、`学样`、`血压`（血压虽未接入，但用户问血压时 DATA 路由命中 → 模板答「血压还没接入，心率血氧可以看」——**比走 lightweight 答"接入了可以查看"正确**，SYSTEM_PROMPT 第 5 条口径一致）；
- 或加 ASR 纠错表（`血阳|学养|学样 → 血氧`）在路由前归一——**推荐后者**（归一后 DATA 命中 + 日志清晰），config 加 `asr_normalize` 映射表；
- **「血压」特殊处理**：归一表不把血压→血氧（语义不同！），单独让"血压"命中 DATA 但模板答「血压未接入」（诚实口径，防误报血氧值）。

### 3. 慢路径指代上下文（依赖 ISSUE-0013，可先占位）

- 本轮路由修复后「你再看一下」会走 DATA（上轮 DATA + 指代），不依赖慢路径上下文修复；
- ISSUE-0013（跨路径上下文）仍待修（P1），两者独立，不互相阻塞。
