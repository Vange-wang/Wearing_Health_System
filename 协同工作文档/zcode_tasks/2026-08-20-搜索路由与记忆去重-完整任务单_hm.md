## 任务 1：联网搜索路由覆盖不足（P1）

### 1.1 问题（真机实测 2026-08-20 19:29-19:31）

| 用户原话（ASR） | 路由 | 问题 |
|---|---|---|
| 我让你查一下广东医科大学的情况 | ❌ lightweight | "查一下"不在词表 → 答「查不了，得联网搜索才行」 |
| 你觉得广东医科大学怎么样 | ❌ lightweight | "怎么样"不在词表 → 无搜索 |
| 你不是能连网查了吗 | ❌ lightweight | 同上 |
| 帮我查一下东莞今天的天气（对照✅） | ✅ hermes | 命中"帮我查" → 搜索成功 |

**根因**：`tool_keywords` 缺自然口语高频词。

### 1.2 阶段 1：扩充 config 词库（先做，最小改动）

`config.yaml` `router.tool_keywords` 追加（**重点：查/看/找 三个祈使词族**）：

```yaml
tool_keywords: [查快递, 写文件, 发邮件, 定时, 搜网页, 搜索, 查天气, 帮我查, 天气, 新闻, 快递, 股票, 股价, 路况, 彩票, 汇率,
  查一下, 查查, 查下, 看一下, 看看, 看下, 找一下, 找找, 找下, 怎么样, 的情况, 如何, 好不好, 是什么, 了解下, 介绍下]
```

- 追加不打乱顺序（git diff 清晰）；宽词（怎么样/是什么）可能误命中闲聊 → 代价=慢几秒+一次搜索，可接受，阶段 2 兜底。

### 1.3 阶段 2：路由语义增强（阶段 1 后做）

宽词命中加长度/结构校验（router.py）：
1. 命中宽词且句长 ≥5 字 → HERMES（实体查询）；句长 <5 → 按原逻辑（可能指代/闲聊）；
2. 或识别「(2~6字实体词)+(宽词)」结构 → HERMES；
3. 能力询问判定（能不能/能否/会不会）**保持现有顺序 0 优先，勿破坏**。

### 1.4 任务 1 验收

## 任务 2：记忆去重失效修复（P1，方案 B 审查裁决）

### 2.1 问题（真机验收暴露，SERIOUS）

同一事实「单车是 FACTOR OSTRO VAM」被记录 **7 条**（措辞不同）。根因：`memory.py:60-62` 纯文本子串去重，无法识别语义重复。违反验收第 3 条「重复不积累」，长期打满 100 条/8KB 上限。

### 2.2 方案对比（zcode 报告）与 Hermes 裁决

| 方案 | 思路 | zcode 自评 | **Hermes 裁决** |
|---|---|---|---|
| A 归一化输出 | 强制「类别:主体:属性值」结构 | 不可靠 | ❌ 弃（措辞仍会漂移） |
| **B 关键词重叠度** | 提取附带关键词集，重叠度 >0.6 判重 | 推荐 | ✅ **采纳（含 2 处修正，见下）** |
| C 提取时先查重 | prompt 喂 user_facts 摘要，输出 DUP | 备选 | 保留备选（token 成本高） |

### 2.3 方案 B 实施要点（zcode 方案 + Hermes 修正）

1. **存储格式**：`2026-08-20 | 类别 | 事实 | 关键词1,关键词2`（四段）；旧条目无关键词 → 子串匹配兜底；
2. **提取层**：REMEMBER 行改 `REMEMBER: <类别>: <事实> ;; 关键词: k1,k2`，prompt 要求关键词=专有名词（品牌/型号/人名/地名/数值），过滤泛化词/停用词；
3. **去重逻辑**（memory.py add_fact）：子串兜底 → 关键词重叠度 `交集/较小集 ≥0.6` 判重跳过；
4. **Hermes 修正 ①**：关键词集合 **<3 个时阈值提高至 0.8**（小集合 0.6 太松，易误杀不同事实）；≥3 个保持 0.6；
5. **Hermes 修正 ②**：同义词归一不止「单车=自行车」——建议提取 prompt 直接要求「车型类统一输出『单车』，品牌/型号保留原文」，**不建代码级同义词表**（减少维护面）；若真机仍漂移再补表；
6. remove_by_keyword 保持现有包含匹配（不受新字段影响）。
