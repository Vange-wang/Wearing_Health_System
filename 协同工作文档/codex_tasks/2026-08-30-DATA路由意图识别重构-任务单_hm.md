# codex 任务单：DATA 路由意图识别重构（语义级，弃关键词穷举）

- **下达方**：Hermes（审查）· 2026-08-30 · Vange 拍板「不能再靠限定关键词，太窄了」（**归属 codex 实施**）
- **状态**：待 codex 实施（SERIOUS——语音查询核心体验）
- **相关文件**：`voice-bridge/app/router.py`、`app/pipeline.py`、`app/llm.py`、`config.yaml`

## 问题本质（Vange 定性）

当前 `data_keywords=[心率,血氧,血压]` + `kw in text` 纯子串匹配，把「含健康词」等同于「查当前数据」，导致：

```
❌ 「心率的正常范围是多少」→ DATA 报当前值（应答科普）
❌ 「心率为什么突然变快」→ DATA 报数值（应解释原因）
❌ 「血氧仪怎么选」      → DATA 报血氧值（应选购建议）
```

**根因**：router 用关键词抢走了本该属于 LLM 的意图判断。SYSTEM_PROMPT（llm.py:50）本已写好「用户问心率/血氧多少会直接报实测值，不由你回答；其他健康问题由你回答」——**这个语义分工是对的，但 router 的裸词匹配把它破坏了**。

## 修复原则（不再穷举关键词）

**router 只做"确定性拦截"，意图判断还给 LLM**：

1. **DATA 模板直答**（router 保留，但收窄到**纯查询句式**）：只匹配明确的「查当前测量值」意图——如「(我的/现在的)心率(是多少/多少/怎么样)」「血氧多少」等查询短语，才走模板直答（确定性报数，防 LLM 读错数）；
2. **其余含健康词的句子**：**不再被 DATA 拦截**，自然落到 lightweight（DeepSeek 裸模型）——由 LLM 理解用户意图：
   - 「心率的正常范围」→ LLM 答科普知识
   - 「心率为什么变快」→ LLM 解释原因
   - 「血氧仪怎么选」→ LLM 答选购
   - SYSTEM_PROMPT 已有此分工，只需让 router 别抢。

## 实现方案

### 方案：查询意图短语匹配（窄）+ LLM 兜底（宽）

**router.py DATA 判定改为**（替代裸词 `kw in text`）：

```
data_queries = [
  "心率多少", "心率是多少", "心率怎么样", "心率如何", "心率咋样",
  "血氧多少", "血氧是多少", "血氧怎么样", "血氧如何", "血氧咋样",
  "心率血氧", "心率跟血氧", "心率和血氧",  # 双字段查询
  "测一下心率", "测一下血氧", "查一下心率", "查一下血氧",  # 祈使查询
  "血压多少", "血压是多少",  # 血压查询（答未接入）
]
```

- 命中查询短语 → DATA 模板直答；
- 未命中 → 落 lightweight/RAG，由 LLM 理解意图。
- **白名单裁剪原则（zcode 审查 P2-1）**：只放**最无歧义的核心查询短语**（"XX多少/是多少/怎么样"）；**所有带前缀修饰的变体（我的/现在/当前/帮我看看）一律不放白名单**——「我的心率」会误命中「我的心率的正常范围是多少」，交给「注入+LLM」兜底，兜底能报数后白名单窄没有代价、宽才有代价。

### 关键设计（zcode 审查 P1：必做，兜底路径承重墙）

- **轻量通道注入健康数据（必做，非可选）**：lightweight 的 `_system_prompt` 在健康数据新鲜时，注入一行「当前健康数据：心率 X、血氧 Y（Z 秒前）」；
- **SYSTEM_PROMPT 条文同步修改（必做，zcode 复审 P2 补全）**：把现行「用户问心率/血氧多少会直接报实测值，不由你回答」改为覆盖**三态**：
  - 已注入当前实测数据 → 「可直接引用该数值」；
  - 未注入 / 数据已过期 → 「如实说明暂无最新数据，不得编造数值」；
  - 其他健康知识问题 → 正常回答；
- 二者是同一件事的两半：只收窄白名单不改这两处，白名单漏掉的变体（帮我看看心率/心跳多少）落到 lightweight 后会被「不许报数」条文拒绝，比现在更糟；而只改"可引用"不写"无数据不得编造"，LLM 在数据过期时可能编造数值。

### 排除词（zcode 复审 P3：防"关系类"残留误拦）

白名单短语「心率跟血氧」「心率血氧」会误命中「心率跟血氧是什么关系」「心率血氧的正常关系」——这类**关系/区别/科普问句**含白名单短语但意图是问知识，需在 DATA 判定前加排除：

- 句子含「关系/区别/正常范围/为什么/原理/是什么关系」等**知识类词**时 → **不走 DATA**（即使含查询短语），落 LLM/RAG 答知识；
- 排除词判定在查询短语匹配**之前**。

### 首字红线

- 查询短语匹配是字符串比对（微秒级），**不增加任何延迟**；
- lightweight 注入健康数据 = 现有 USER.md 注入同机制（本地文件/内存读，微秒级），**不增加首字**；
- 不新增 LLM 调用、不新增网络请求。

## 验收（真机 + 单测，覆盖"该报数"与"该答知识"两类）

| 输入 | 期望 |
|---|---|
| 我的心率多少 / 血氧是多少 | DATA 报真实值（不回退） |
| 心率跟血氧 | DATA 双字段（不回退） |
| 你再看一下 | 上轮 DATA 延续（不回退） |
| 血阳是多少（ASR 归一） | DATA 报血氧（不回退） |
| 血压多少 | DATA 答「血压未接入」（白名单已含血压短语，对齐） |
| **帮我看看心率**（白名单外变体） | **lightweight 报注入的真实值**（非拒绝、非编造，P1 必做验收） |
| **心率的正常范围是多少** | **lightweight/RAG 答科普**（非报当前值） |
| **心率为什么突然变快** | **lightweight 答原因**（可结合当前数据，非单纯报数） |
| **心率跟血氧是什么关系** | **lightweight/RAG 答知识**（排除词拦截，非 DATA 报双字段值） |
| **血氧仪怎么选** | **lightweight/慢路径答选购** |
| **数据过期（>5min）问心率多少** | **如实说明暂无最新数据，不编造**（SYSTEM_PROMPT 三态） |
| 回归 | 全量单测绿（含新路由用例） |
