# 会话交接规范（Hermes / zcode）

> 对齐 WorkBuddy 的 WB_handoff 机制，扩展给 Hermes 和 zcode。
> 目的：任一线程/会话上下文将满（或用户指示）时，产出交接文档，新线程/新会话读最新文档即可开工，不丢失上下文。

## 一、触发时机

1. 用户（Vange）说「线程太满」「交接」「换线程」时；
2. Agent 自身检测到上下文将满（如 Hermes compaction / 长会话）时；
3. 一段大任务完成后主动交接（可选）。

## 二、交接三步

1. **总结**：按下方模板总结当前状态（现状/已完成/未完成/阻塞/下一步）。
2. **存盘**：写入交接目录，命名 `YYYY-MM-DD-交接-线程N_<后缀>.md`（后缀 = agent：`_hm` / `_zc`）。一交接一文档，**不覆盖**旧文档。
3. **开工**：新线程/新会话读**最新一份**交接文档即可恢复上下文。

## 三、目录

- 本目录：`协同工作文档/会话交接/`
- 历史：WorkBuddy 旧机制保留在 `WB_handoff/`（WB 已暂停，只读参考）

## 四、模板字段（每份交接文档必须含）

| 字段 | 说明 |
|---|---|
| 一句话现状 | 当前项目/任务处于什么状态 |
| 已完成（本线程）| 本线程内做过的关键事项 |
| 未完成（带优先级）| 剩余事项 + P1/P2/P3 |
| 阻塞点 | 卡在哪（硬件未到/等某人/外部依赖）|
| 关键文件（绝对路径）| 下一步要用的文件路径 |
| 下一步动作 | 新线程开工第一件事 |
| 规范提醒 | agent.md 关键条款（后缀/审查/模型守卫）|

## 五、注意

- 交接文档是「状态快照」，不是过程日志——写清**下一步能直接开工**的信息即可。
- 交接后旧线程可关；新线程以最新交接文档为准，配合 `session_search`（Hermes）回溯细节。
- 文件后缀遵循 agent.md §5.1（`_hm` / `_zc`）。
