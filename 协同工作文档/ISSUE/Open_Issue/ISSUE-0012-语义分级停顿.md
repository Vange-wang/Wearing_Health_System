## 描述

句间连读修复（commit 61d21c4）落地了「语义转折正确分句 + 正常停顿」，但所有句级边界（。？！～…；）仍统一 300ms 发帧间隔。原始诉求中「按语义决定是否稍长间隔」尚未实现：**话题切换处应停顿更长（~600ms），普通句间保持 300ms**，让听感更接近真人对话的段落感。

## 实现要点（Spec 评估时展开）

1. 分句器输出边界类型（普通句界 / 话题切换），需定义话题切换的判定信号（如 `\n`、连续强标点、或提示词约定输出标记）；
2. pipeline 按边界类型分级 `sentence_gap_ms`；
3. 若需设备侧配合（帧内嵌停顿 vs 发帧节奏），评估帧协议是否扩展。

注意：设备为顺序播放，服务端发帧节奏部分被预缓冲吸收，**长停顿建议以帧内嵌静音实现**（参考查证 §2.1：edge 句尾内嵌 ~610ms 静音是当前句间停顿的实际载体）。

## 关闭条件

- 话题切换处停顿 ≥0.5s（实测听感/帧静音量化），普通句间不劣化（≤0.35s 语义不碎）；
- Spec 补条目 + 单测 + 真机听感确认。
