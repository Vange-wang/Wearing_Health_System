# zcode 任务单：遗忘不彻底——关键词字段残留泄漏（SERIOUS）

- **下达方**：Hermes（审查）· 2026-08-20 · 真机验证暴露
- **状态**：待 zcode 实施
- **相关文件**：`~/.hermes/scripts/memory_server.py`（Hermes 侧，若走 Hermes 修则本任务单作废，见下）

## 问题（真机复现 2026-08-20 21:07）

用户让 BOX-3「忘掉身高」→ memory_server DELETE 删除了身高条目 ✅，但**微信端仍答出"身高 180cm"**。

**根因**：另一条目的**关键词字段残留**了被遗忘的信息：
```
2026-08-20 | 身体 | 体重55kg | 55kg,180cm   ← 180cm 残留在关键词里
```
- 遗忘"身高"只删含「身高」关键词的条目；
- 体重条目的关键词 `55kg,180cm` 不含「身高」→ 未被删除；
- Hermes/voice-bridge 注入时读到 `180cm` → 答出身高 → **遗忘不彻底**。

**本质**：关键词字段是记忆的一部分，遗忘时必须**全局扫描所有条目的关键词**，而不只是删除匹配条目。

## 修复要求（voice-bridge 或 Hermes 侧，择一实施）

### 方案：遗忘时全局清理关键词

1. `remove_by_keyword(keyword)` 语义扩展为两步：
   - **步骤 1（删条目）**：删除**事实文本**或**关键词**含 keyword 的整条（现状）；
   - **步骤 2（清残留）**：对**保留的所有条目**，从其关键词字段中**移除**匹配 keyword 或与 keyword 语义相关的关键词（如忘「身高」→ 清掉其他条目关键词里的「180/180cm/身高」）；
   - 若步骤 2 后某条目关键词为空 → 保留事实，关键词置空（或删字段，取决于格式约定）。
2. **语义关联关键词**：仅删与 keyword 字符串匹配的还不够（「身高」vs「180cm」字面不匹配）——需要**同义词/关联词扩展**：
   - 简单版：提取时关键词里本就含数值（180cm），遗忘「身高」时同时清理「180/180cm」——建议在 memory_server 维护小型关联词表（身高↔180cm 这类数值归属）或要求提取层把「身高=180cm」存为**属性-值对**而非平铺关键词；
   - 更稳版：把事实条目结构化为 `属性: 值`（`身高: 180cm`），遗忘按属性删值——推荐长期方向，改动大，可拆二期。

## 建议实施顺序

1. **立即**：Hermes 侧 memory_server 增加步骤 2（全局清关键词残留）——改动小（~15 行），且能覆盖已有数据；
2. **二期**：提取层把事实存为 `属性: 值` 结构，遗忘按属性精确删——语义彻底。

## 验收

2. 体重等其他事实**保留完整**（不被误删）；
3. 回归：既有遗忘/去重单测通过。
