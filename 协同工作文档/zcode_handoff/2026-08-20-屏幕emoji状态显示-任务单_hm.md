## zcode 完成情况（实施记录，供 Hermes 复审）

### 落地内容

1. `voice_agent.c`：删除 RGB LED 测试代码，集成 LVGL（`display_init` 照抄 image_display）、`health_probe_ok`（GET /health 解析 `last_probe_ok`，超时 2s）、`status_task`（30s 轮询 + WiFi 变化即时重判）；
2. `CMakeLists.txt`：加 `spiffs_create_partition_image` 打包 emoji PNG；
3. `spiffs/`：4 个 emoji PNG（😄u1f604 / 😵u1f635 / 🤐u1f910 / 🌚u1f31a，128×128 RGBA，Segoe UI Emoji 字体生成）。

### 实施中发现并修复的问题（共 4 个）

1. **emoji PNG 字形裁切**：Segoe UI Emoji 字形有负顶部偏移（-46~-56px）且宽度超画布，初版 285×285 画布导致上边/右边被裁。改用 500×500 大画布 + 安全绘制起点重新生成，真机确认完整。
2. **😵 态逻辑缺陷**：初版 WiFi 断时仍调 `health_probe_ok()` 必然失败，导致 😵 永远到不了。改为 WiFi 断时用 vb 缓存（上次 WiFi 正常时的探测结果）。
3. **mDNS 解析失效需人工复位**：WiFi 断重连后 mDNS 客户端状态失效（`getaddrinfo 202`），代码只在首次拿 IP 初始化一次。改为 WiFi 断开时释放 mDNS、重连拿 IP 后重建。
4. **WiFi 断网后不自动重连**：原 `wifi_task` 断开后只扫描一次，失败（热点广播未恢复/无匹配凭据）就永久卡断。改为内层 `while(!s_wifi_up)` 持续重试扫描 + 指数退避（1s/2s/4s…封顶 30s）。

> 问题 3/4 是**原任务单范围外、真机验证中暴露的稳定性缺陷**，已一并修复。真机连续两次「关热点→😵→开热点→自动回😄」验证通过，无需人工复位。
