## 需求（Vange 拍板 2026-08-20）

状态灯做不了（灯2 GPIO 未定位 + MCLK/GPIO2 复用冲突）→ **改为屏幕显示状态 emoji**：

| 状态 | emoji |
|---|---|
| voicebridge 可用 + WiFi 可用 | 大笑 😄 |
| voicebridge 可用 + WiFi 不可用 | 晕乎乎 😵 |
| voicebridge 不可用 + WiFi 正常 | 闭嘴 🤐 |
| 两个都不行 | 黑脸 🌚 |

- **退步 2 态**（若 4 态显示/切换有问题）：正常 = 😄，不行 = 🌚（Vange 已授权）；
- 断电黑屏、有电显示对应 emoji；
- **本期先验证：不同状态能否显示对应 emoji**。

## 可行性结论（Hermes 已查证）

1. 屏幕 + LVGL 9.5 链路已验证（image_display 示例真机显示过，含 SPIFFS PNG + backlight）；
2. voice_agent.c 当前**零 LVGL 代码**——需集成 `bsp_display_start_with_config` + LVGL 锁；
3. emoji 必须用 **PNG + lv_img**（montserrat 字体无 emoji 字形，label 直写变豆腐块）；
4. 状态来源现成：WiFi = 固件本地；voicebridge = `GET /api/v1/health` 的 `tts.last_probe_ok`（服务端已就绪）。

## 实施要点

1. 屏幕初始化照抄 image_display.c app_main（bsp_i2c_init → bsp_display_start_with_config → backlight_on → display_lock 内建 UI）；注意 LVGL 9.5 API（lv_event_get_user_data 等，image_display 已适配）；
2. emoji PNG 放 SPIFFS `S:/spiffs/`（😄 可用 LVGL 自带 F600.png，其余 3 个自备，≤200×200）；SPIFFS 烧录参考 image_display 的 storage.bin 流程；
3. 状态任务：每 30s 或 WiFi 状态变化时判定 → `lv_img_set_src` 切换；health 轮询超时 2s 判不可用；
4. 先 4 态；真机有问题降 2 态（同套判定合并）。

## 验收

真机依次模拟 4 种状态（正常 / 断 WiFi / 停 voice-bridge / 都断）确认 emoji 正确切换；断电黑屏、上电显示。
