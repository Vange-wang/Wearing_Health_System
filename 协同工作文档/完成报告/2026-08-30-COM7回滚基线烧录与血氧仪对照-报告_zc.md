# zcode 报告：COM7 回滚基线烧录 + 信号质量对照实测

- **产出方**：zcode · 2026-08-30
- **性质**：腕部节点信号质量排查（线程 N+3 交接的 P1 级任务）阶段性实测报告
- **涉及板卡**：COM7（ESP32-C3 腕部节点，本次为空 flash 新板）

## 一、目的与方案

交接文档（`zcode_handoff/2026-08-23-交接-线程N+3_zc.md`）遗留问题：COM6 腕部节点 FFT 实测心跳频带能量仅 17-20%，算法层反复修补无效，怀疑信号采集层物理衰减。本次用**回滚对照法**验证：

1. 从归档仓库 `bd9e564~1` 提取 P1 已知良好固件（纯峰检测 hr_spo2.c 6324 字节 + **LED 0x0F=3mA** + 10s 窗口 + 5s/帧）；
2. **副本构建**：复制工程至 `D:\esp-box\examples\ble_wrist_node_rollback\`，替换 main/ 全套文件后编译烧录——不触碰 Codex 正在重构的工作树（其 signal_diag/selftest 等新文件原样保留）；
3. 构建脚本留档：`D:\esp-box\build_wrist_rollback.py`（端口 COM7）。

## 二、烧录与启动验证

- COM7 烧录前状态：空 flash（ROM 反复打印 `invalid header: 0xffffffff`）；
- 编译烧录一次通过（FLASH_EXIT=0，Hash verified），IDF v5.2.7，App version `b321e96-dirty`；
- 上电启动日志关键行：

```
max30102: 初始化完成 PartID=0x15（软件I2C/100Hz/215µs/3mA）   ← 传感器 I2C 正常，3mA 确认
wrist: 腕部节点就绪：广播 WH-Wrist01，5s/帧
hr_spo2: RAW n=1024 irDC=397-408 ...（手指未检测到）           ← 10s 窗口（1024 样本@100Hz）正确
```

无手指时 irDC≈400，正确判"手指未检测到"，不输出 HR/SpO2。

## 五、最终结论

1. **回滚基线有效**：P1 固件 + 3mA 在 COM7 上真值帧精度达标，基线可用（副本工程与脚本留档，可随时复烧）。
2. **信号衰减根因定性：COM6 板物理层问题**（模块个体差异/光路接触结构/油污三选一）。同固件在 COM7 上 irAC 170-656、irDC 漂移 ±500，均为健康水平——排除固件、LED 电流策略与系统性原因。
3. **切迹伪峰与信号强度正相关**：COM7 强灌注（irDC≥54k）时 3mA 也能触发 2× 伪值；COM6 弱信号反而不易触发。即"横跳"（算法门限问题）与"不出数"（硬件信号问题）是两个独立问题。
4. **对重构批次 2 的建议**：P1 简单峰检测在强灌注场景会输出 2× 伪值（本次 139-176），生产路径的质量门应保留切迹抑制（bd9e564 已有实现可参考），否则强信号用户会复现此缺陷。
