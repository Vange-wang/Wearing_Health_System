# 语音遗忘指令缺口报告：英文名未真正遗忘（双记忆源冲突）

- **起草**：zcode（开发员）· 2026-08-20
- **性质**：缺陷/边界问题报告（真机测试暴露）
- **对象**：任务 3「遗忘指令真机补测」验证结果 + 暴露的架构边界缺口
- **结论**：遗忘机制**功能正常**（voice-bridge 层删除成功），但英文名仍被答出——根因是**同一事实存在两个记忆源**，遗忘指令只删了 voice-bridge 那一份，Hermes USER.md 里的画像未被删。**属架构边界缺口，非代码 bug。**

---

## 一、现象复现（2026-08-20 真机）

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 语音说「我的英文名是 Vange」 | `user_facts.md` 自动沉淀：`[称呼] 用户的英文名字是Vange` ✅ |
| 2 | 语音说「忘记我的英文名」 | 日志 `记忆遗忘删除 1 条: 英文名字`，`user_facts.md` 该条已删 ✅ |
| 3 | 再问「我叫什么名字」 | ❌ 仍答出 Vange |

## 二、根因（已定位）

英文名 Vange 存在于**两个记忆源**：

| 记忆源 | 位置 | 内容 | 遗忘指令是否覆盖 |
|---|---|---|---|
| voice-bridge 语音记忆 | `voice-bridge/memory/user_facts.md` | 本次语音说「英文名 Vange」沉淀的条目 | ✅ 覆盖（`remove_by_keyword` 已删） |
| Hermes 持久画像 | `~/.hermes/memories/USER.md` 第 11 行 | `Name: WANG ZHAN / 王瞻. English name: Vange. ...` | ❌ **不覆盖** |

流程：`LightweightLLM._system_prompt()` 每轮注入时**先读 USER.md（Hermes 画像，只读）**，再追加 `user_facts.md`（语音记忆）。所以即使语音记忆删了，USER.md 里的 `English name: Vange` 依然每次注入，小V 自然答得出。

## 三、为什么会有这个缺口（Spec 红线）

Spec 需求 3 §3.3 明确了两条设计约束，正是这个缺口的来源：

1. **不写回 USER.md**（§3.3 第 110 行）："voice-bridge 直接写会冲突/越权"——Hermes memory 有字符上限 1375、且是 Hermes 侧管理的画像文件；
2. **双向同步不在本期**（§3.3 第 132-135 行）："语音记忆先独立沉淀；需进入 Hermes 主记忆时由 Hermes 侧定期/手动 review user_facts.md 合并入 USER.md，voice-bridge 不越权写；本期不做自动双向同步，留 ISSUE 登记"。

因此，`remove_by_keyword` 只删 voice-bridge 自己的 `user_facts.md`，是**符合 Spec 的预期行为**。但真机暴露出这个边界在「遗忘」场景下不完整：用户说「忘记」，只清了一边，另一边还在。

## 四、影响评估

| 场景 | 影响 |
|---|---|
| 用户语音新说的信息（如单车型号 FACTOR OSTRO VAM） | 遗忘指令能彻底删（只存在 user_facts.md）✅ |
| 用户信息**同时存在 USER.md 和 user_facts.md**（如英文名 Vange） | 遗忘指令只能删语音那份，USER.md 那份还在 ❌ |
| 用户信息只存在 USER.md（Hermes 早知道的画像） | 遗忘指令完全无效（本来也不在 user_facts.md）❌ |

## 五、可选修复方案（请 Hermes/Vange 拍板）

### 方案 A：遗忘指令同步删除 USER.md（打破"不越权写"红线）

- voice-bridge 的 `remove_by_keyword` 同时删除 user_facts.md 和 USER.md 中匹配的条目；
- **优点**：遗忘语义彻底；
- **缺点**：违反 Spec §3.3「voice-bridge 不越权写 USER.md」红线；可能误删 Hermes 侧其他 agent 共用的画像。

### 方案 B：遗忘指令只删语音层 + 明确告知（保持红线，改进交互）

- `remove_by_keyword` 保持只删 user_facts.md；
- 提取层/回复层在遗忘后提示「如果这个信息在其他地方也记得（如微信小V），需要到那边也删一下」——但语音场景提示体验差。

### 方案 C：Hermes 侧提供遗忘接口，voice-bridge 转发（推荐，符合分层）

- Hermes 侧暴露一个「删除 USER.md 指定画像」的接口（由 Hermes memory 工具管理，不越权）；
- voice-bridge 的遗忘指令先删 user_facts.md，再调用 Hermes 遗忘接口删 USER.md 对应条目；
- **优点**：遗忘彻底 + 不破坏分层（删除动作仍由 Hermes 侧执行，voice-bridge 只发起请求）；
- **缺点**：需 Hermes 侧新增接口，工作量在 Hermes。

### 方案 D：维持现状 + 登记 ISSUE（最小改动）

- 承认这是 Spec 已知边界（§3.3 已注明"本期不做双向同步"）；
- 登记 ISSUE 到 `协同工作文档/ISSUE/Open_Issue/`，待后续「双向同步」立项时一并解决。

## 六、建议

**推荐方案 C**（Hermes 提供遗忘接口，voice-bridge 转发）：遗忘语义彻底且不破坏"voice-bridge 不越权写 USER.md"的分层原则。若短期不想动 Hermes，退而**方案 D**（登记 ISSUE，承认已知边界）。

**待 Hermes/Vange 拍板后实施。**
