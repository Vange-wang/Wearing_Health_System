## 2. 三句口语实测（Spec §9.3，同 v0.1 三句，墙钟 open_ms）

测量工具：`voice-bridge/measure_v02.py`（httpx `trust_env=False` 直连，流式逐块读取）。**每项验收口径**：三句平均 open_ms ≤ 1500ms（Spec §9.1.2），峰值超标不计入 fail（§11）。

### 优化前（初版，TTSEngine 每句先试 edge 慢失败 ~1s）

| 句子 | open_ms | asr | llm_ttft | tts_first | 帧数 |
|---|---|---|---|---|---|
| 01 今天天气怎么样 | 4172 | 149 | 1953 | 1545 | 1 |
| 02 帮我查一下心率 | 2548 | 251 | 619 | 1376 | 2 |
| 03 你叫什么名字 | 2186 | 247 | 529 | 1134 | 2 |
| **平均** | **2969** | | | | |

→ 超标。根因：edge 现网 403，但 TTSEngine 每句合成仍先等 edge 慢失败（~1s）再落 piper。

### 修复（edge 已知宕机时短路直走 piper）后 —— 稳态两轮

| 句子 | open_ms | total_ms | asr | llm_ttft | tts_first | 帧数 |
|---|---|---|---|---|---|---|
| 01（轮A） | 1579 | 1844 | 222 | 526 | 361 | 2 |
| 02（轮A） | 1491 | 1497 | 282 | 633 | 222 | 1 |
| 03（轮A） | 1441 | 1750 | 240 | 684 | 232 | 2 |
| **轮A 平均** | **1504** | | | | | |
| 01（轮B） | 1723 | 1726 | 239 | 724 | 307 | 1 |
| 02（轮B） | 1601 | 1603 | 264 | 754 | 335 | 1 |
| 03（轮B） | 1449 | 1453 | 240 | 678 | 229 | 1 |
| **轮B 平均** | **1591** | | | | | |

（total_ms 取自服务端 `request_done` 结构化日志，为墙钟全链路耗时。）

冷启动离群（服务刚重启的首句）open_ms 达 3736ms（DeepSeek 首 token 2381ms），稳态后回落。

**多句回复逐帧到达记录**（裁决②证据补强）：轮A-01 两帧、客户端首末帧间隔 258ms；轮A-03 两帧、间隔 298ms；对应服务端 `stream_done` 日志 `sentence_count=2 / tts_total > tts_first`，证明首帧发出后仍有后续句在合成发送。

### 结论（经 Hermes 裁决后定稿）

- **open_ms 稳态平均 1504~1591ms**：按裁决①「有条件接受」口径（验收对象=稳态三句平均、剔除冷启动离群、达标线 ≤1600ms、超标须归因 DeepSeek 首 token）——两轮均 ≤1600ms，且最大单项均为 `llm_ttft_ms`（526~754ms），归因成立，**有条件通过**。
- 延迟构成（稳态）：`ASR ~240ms` + `DeepSeek 首 token ~650-750ms` + `首句完成 ~150-300ms` + `piper 首句 ~230-360ms`。其中 **DeepSeek 首 token 是唯一不可控大项**（Spec §11 已列为已知风险）。
- **流式可感**：按裁决②终稿口径，流式真实性 = 多句回复下逐帧到达（帧数 ≥2 且帧间隔 >0），单句回复豁免全部流式判据。实测多句回复逐帧到达记录见 §2（间隔 258~298ms + stream_done 日志 sentence_count≥2 且 tts_total>tts_first），**通过**。深层观察：≤50 字约束下 DeepSeek 常在首帧发出前已生成完，流式「边生成边播」实质收益有限，但流水线本身是流式的（stream=True + 分句 + 逐帧编码 + chunked，T9/T10 证明），回复变长后收益自然体现。
