## 本次代码与运行核对

电脑服务由 `service_control.service_host` 加载 `app.main:app`，端口 8710 健康接口返回正常。盒子的 USB 当前离线。`voice-bridge/app` 与回退提交 64bc1b99 的文件集合和内容一致，比较时归一化 CRLF。最近安装镜像属于历史回执，本次未读板上镜像。

主调用链为 BOX3 唤醒与收音 → v2 帧上传 → VoiceV2Service 识别和选路 → 普通聊天、天气或网页搜索 → StreamingPipeline 分句合成 → 设备音频、字幕与搜索元数据 → 播放回执。设备鉴权先于会话分配。接口健康未覆盖这条真机链路。

本次运行152个独立选定用例，复跑不重复计数，149通过、3失败。搜索动画、时效性、网页路由、v2回执、音频输入的29项全部通过。其余123项覆盖pipeline、router、首段交付、健康身份、设备鉴权、分句和任务清理，其中120项通过。失败集中 `voice-bridge/tests/test_first_segment_delivery.py`，两项浮点等待值要求与扣除已耗时的实现冲突，另一项close异常后历史提交期待与后续交付语义Spec冲突。单文件复跑仍失败，需核对测试契约。此结果覆盖选定用例，整个仓库测试尚未全跑。命令与结果见[测试摘要](测试报告/2026-11-11-项目摸底测试摘要.md)。

健康数据链路为 ESP32-C3 + MAX30102 节点 → BLE综合帧 → BOX3双连接与各自缓存 → 选择一个有效来源上报 → 主机新鲜度和身份校验 → 健康口播。当前独立传感固件工程为 `Code文档/固件/wrist_node/`，双节点使用相同协议；本次未查到独立胸部固件工程。现行健康API上报一个选定有效来源，双用户独立查询尚未实现。稳定放置的历史读数对照不能覆盖运动、低质量读数和双BLE共存下的首字表现。

现用固件通过本机 `.work/box3/wake-first-20261108/build` 基底加覆盖对象构建，并依赖相邻 ESP-BOX 组件目录。旧 `Code文档/固件/box3_voice_agent/` 与运行版文件集合不同。从干净检出到完整镜像的可重复构建尚待验证。
