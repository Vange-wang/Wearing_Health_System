## 3. 选型结论

### 3.1 判决句

> **ESP-IDF v5.2.7 为本项目 ESP32-S3 便携式 AI 终端的唯一开发环境；Arduino 路线否决。**

### 3.2 引用关键证据

- **V-02**：esp-box 官方 BSP 对 BOX-3 开箱即用（Kconfig 默认选中 BOX-3，无需手动补 board 定义）。
- **V-03**：屏幕 + 触摸 + 图片渲染全链路走通（Arduino 路线无官方 BOX-3 board + GT911/ILI9341 组合定义）。
- **V-06**：chatgpt_demo 证明「屏幕 + 双麦 + 喇叭 + WiFi + esp-sr 离线唤醒」完整技术栈可在真实硬件上初始化并稳定运行。
- **V-08**：16MB Octal PSRAM 原生识别并入堆（Arduino 需手改 board 配置）。
- **V-12**：ESP-SR 语音组件（唤醒词/AEC/降噪/VAD）仅 IDF 路线可编译集成。

### 3.3 否决 Arduino 的具体原因

1. 无官方 ESP32-S3-BOX-3 board 定义，需自行维护 pinmap（ILI9341 + GT911 + ES8311 + ES7210 + NS4150 功放）。
2. 缺少 ES7210 双麦 ADC / ES8311 codec 的成熟 Arduino 驱动，录音/播放会陷入底层移植。
3. ESP-SR 离线语音组件无 Arduino 发行版，无法满足「离线唤醒词 + 前端增强」的核心需求。
4. Octal PSRAM（16MB）与 DMA 缓冲需手动配置，错误率高。

（对比路线 V-A1~V-A4 未执行：Spec §4.2 标准1 字面为「V-01~V-12 全通过 且 V-06 无坑」，而 V-06 实有坑。经核实，V-06 的坑性质 =「esp-box master 示例 UI 停留在 LVGL8 时代，esp_lvgl_port v2 已升 LVGL9」，属示例代码版本迁移工作量，非 IDF 路线缺陷；移植后 chatgpt_demo 编译零错误 + 全链路初始化成功，恰恰证明 IDF 路线健康。故判定口径由「标准1 已触发」改为「V-06 无坑按『无 IDF 路线缺陷』实质满足」，Spec §4.2 已同步补充此口径，故不再投入 Arduino 验证。）

## 4. 风险清单

### 4.1 已知编译坑（新发现，务必入 Spec 技术验证记录）

| # | 坑 | 影响 | 解法 |
|---|----|------|------|
| R1 | LVGL 9.x 把 `LV_USE_PNG`/`LV_MEM_CUSTOM`/`LV_COLOR_16_SWAP` 等旧 Kconfig 符号**改名或删除**，sdkconfig.defaults 里旧名被静默忽略 | 固件缺 PNG 解码器 / 用 64KB 内置池饿死解码 | 用 `LV_USE_LODEPNG`、`LV_USE_CLIB_MALLOC`，逐项核 `lv_conf_internal.h` |
| R2 | LVGL 9.5 的 `LV_VERSION_CHECK(x,y,z)` 变为**主版本精确相等**（`x==MAJOR && ...`），8.0 检测在 9.x 下为假 | SquareLine 导出的字体 const 分支走错 → 编译冲突 | 端口脚本统一折叠为 const 定义 |
| R3 | LVGL 9.5 SW 渲染器**不支持 ARGB8565**，LVGL8 的 `TRUE_COLOR_ALPHA` 图片（[lo,hi,a] 交织）需解交织转 `RGB565A8` | 移植的图片资源无法渲染 | 字节级解交织脚本 |
| R4 | LVGL 9 把 `lv_indev_t`/`lv_timer_t` 结构体不透明化 | 直接访问 `->driver->`/`->user_data` 编译失败 | 改用 `lv_indev_set_long_press_time()` / `lv_timer_set_user_data()` 等 setter |
| R5 | `esp_codec_dev` 1.1.0 的 `read/write` 返回**状态码**（0=成功）而非字节数 | 把 0 当失败会误判 | 按官方 test 用法 `TEST_ESP_OK(ret)` + 按请求长度累加 |
| R6 | nimble 广播报文打印全是 `MODLOG_DFLT(DEBUG)`，且 `CONFIG_LOG_MAXIMUM_LEVEL` 默认锁 INFO（编译期剔除） | BLE 扫描「无日志」假象 | sdkconfig 设 `LOG_MAXIMUM_LEVEL_DEBUG` |
| R7 | 组件 `espressif/esp-opus` 在注册表**不存在** | Spec 名称过时 | 改用 `78/esp-opus`（1.0.5，IDF≥5.0）；`78/esp-opus-encoder` 需 IDF≥5.3 不可用 |
| R8 | esp-sr ≥1.9 依赖 `esp-dsp <=1.5.0` | 与某些工程锁的 esp-dsp 1.8 冲突 | 依赖解析时统一 esp-dsp ≤1.5 |

### 4.2 环境/工程坑（Windows + BOX-3 特化）

- **MSYSTEM 泄漏**：从 Git Bash 启动的 Python 会带 `MSYSTEM` 环境变量 → idf.py 检测后拒绝执行但**退出码 0**（假成功）。构建脚本必须清 MSYS/MINGW 变量并校验 `flasher_args.json` 存在。
- **safe-delete 钩子**：经 `PYTHONPATH` 的 sitecustomize 注入子 Python，`os.remove` 走回收站失败即 fail-closed → 构建脚本 env 里 pop 掉 PYTHONPATH/PYTHONHOME 绕开。
- **Write 工具会给 ASCII 文件加 UTF-8 BOM**：`partitions.csv` 带 BOM 会被 gen_esp32part 当数据解析报错 → 新工程文本文件落盘后剥 BOM。
- **main 任务栈仅 ~4KB**：栈上大数组会静默卡死（无 canary/WDT）→ 大缓冲一律 static/heap。
- **文件锁瘟疫**：每个 build 目录完整编译一次后被锁死（safe-delete 钩子 + Defender）→ 每轮全新 build 目录 + 一轮只跑一次大编译。
- **USB-Serial/JTAG 枚举竞态**：设备快速重启循环中 COM 口会从 Windows 消失；恢复=拔插 USB；抓串口脚本必须支持断线重开。
- **进下载模式后 Boot 键卡住**：复位仍回 `boot:0x23 DOWNLOAD`；恢复=拔线→连按 Boot 回弹→空手插线。
- **触摸补丁作用域**：`scl_speed_hz=0` 补丁必须覆盖**每个**工程自己的 `managed_components/espressif__esp-box-3/esp-box-3.c`（各工程组件副本互相独立）。

### 4.3 未通过项与硬件问题

- **无未通过项**。
- 硬件差异：BOX-3 触摸芯片实测 GT911（Spec 初稿写 TT21100），BSP 1.2.0~2 已兼容双探测。
- chatgpt_demo 的「设置应用」依赖 TinyUSB 虚拟 U 盘改配置，在 Windows 上枚举不稳定；本项目实际采用**直写 NVS** 方案规避。
