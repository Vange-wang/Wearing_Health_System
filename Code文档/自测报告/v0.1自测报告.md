## 二、三句实测（X-Timing 数据）

测试音频：piper 合成的三句中文 WAV（16k/16bit/mono），存 `audio/` 目录。

| 输入句 | ASR 识别 | LLM 回复（原文） | asr_ms | llm_ms | tts_ms | total_ms |
|---|---|---|---|---|---|---|
| 今天天气怎么样 | 今天天气怎么样？ | 哎呀，我主要管健康这块，天气得靠天气预报App啦！不过天气变化大，出门记得加衣服哦。 | 188 | 2259 | 1854 | 4386 |
| 帮我查一下心率 | 帮我查一下心率。 | 健康数据监测功能即将上线，到时候一定第一时间告诉你哈。 | 217 | 584 | 1199 | 2058 |
| 你叫什么名字 | 你叫什么名字？ | 我叫小衡，你的随身健康小助手！ | 183 | 453 | 1046 | 1732 |

- 语义判定：三句 ASR 识别全部正确；LLM 回复均符合 Spec §6 系统提示词（简短口语化、健康数据回"即将上线"、自报"小衡"）。
- 返回语音：piper 合成 WAV（16kHz），响应文件存 `audio/*.resp.wav`，人耳可懂。
- 延迟分析：total 1.7~4.4s（v0.1 非流式，LLM 等待完整回复是主要耗时；v0.2 流式化后开口延迟目标 1.2~1.4s）。

## 五、偏差与风险（提交 Hermes 审查裁决）

| # | 偏差/风险 | 说明 | 建议 |
|---|---|---|---|
| D1 | **edge-tts 主引擎不可用（403）** | 微软封禁 6.x token；升 7.x 可连但移除 16kHz 输出（仅 24k mp3），转码需引入 ffmpeg/pydub（违反"不引入未列依赖"红线） | v0.1 接受 piper 独撑 TTS；edge 恢复留 v0.2 评估（转码方案 or 换火山/讯飞云 API） |
| D2 | ASR 模型资产名与 Spec 不符 | Spec 写 `sherpa-onnx-sense-voice-zh-20240418`，该资产不存在；实际用官方 `sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`（多语种含中文，int8） | 建议 Spec §8 修正资产名 |
| D3 | piper-tts 1.6.0 Windows 打包 bug | espeak-ng-data 查找用编译机硬编码路径；已通过目录联接（junction）在 `D:\a\piper1-gpl\...\espeak-ng-data` 修复 | 迁移机器时需重建 junction（README 已注明） |
| D4 | edge-tts vendor patch | venv 内 `edge_tts/communicate.py` outputFormat 改为 riff-16khz-16bit-mono-pcm | 重装 edge-tts 会覆盖，需重打 patch |
| D5 | SenseVoice 静音幻觉 | 纯静音会被识别出噪声字符（如"그."），不会返回空 → no_speech 实际由 0 帧音频触发 | v0.2 建议加 VAD 或能量门限 |
