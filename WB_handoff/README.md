# WorkBuddy 会话交接规范（WB_handoff）

> 本文件夹（`WB_handoff/`）用于 WorkBuddy 会话线程交接。当旧线程「太满」（上下文过长 / token 接近上限 / 需要换新线程）时，把旧线程进度总结成一份交接文档存到这里；新线程启动后读取该文档即可无缝续接、马上开工。

---

## 一、什么时候用（触发时机）

由 Vange 判断并下达指令：「当前线程太满，做一次交接」。

WorkBuddy 收到该指令后，执行下面的交接动作，不需要 Vange 逐条说明。

---

## 二、交接动作（WorkBuddy 执行，三步）

1. **总结旧线程**：梳理当前线程的主要内容、已完成任务、未完成任务、阻塞点、关键文件路径、下一步动作。
2. **写交接文档**：严格按下方模板填写，不要遗漏字段。
3. **存盘**：写入 `WB_handoff/` 目录，文件命名 `YYYY-MM-DD-交接-线程N.md`（N 递增，如 `2026-08-16-交接-线程6.md`）。

---

## 三、交接文档模板（照此填写）

```markdown
# 会话交接：<日期> · 线程 <N>

## 项目
可穿戴健康辅助系统

## 交接原因
<旧线程 token 太满 / 上下文过长，需开新线程继续>

## 一句话现状
<当前项目整体进行到哪一步，一句话说清>

## 已完成（本线程内）
- [x] <具体完成的事，含关键结果/证据路径>

## 未完成（新线程继续，按优先级排序）
- [ ] <任务 + 优先级 P0/P1/P2/P3 + 下一步怎么做>

## 阻塞点 / 待决策
- <卡在哪、等谁拍板、最小解锁输入>

## 关键文件 / 路径
- <Spec、代码、报告、issue 库等绝对路径清单>

## 下一步动作（新线程开工第一步）
1. <第一个要做的事，明确到可直接执行>

## 关键规范提醒
- 模型守卫：代码开发必须 Kimi K3，动工前向 Vange 核实
- 审查报告落盘：协同工作文档/审查报告/
- issue 库：协同工作文档/ISSUE/（ISSUE-XXXX 编号）
- 协作规范：agent.md v1.3
```

---

## 四、新线程开工流程

1. 新线程启动后，**先读 `WB_handoff/` 下最新的交接文档**（按文件名日期找最新）。
2. 据此了解：项目现状、已完成、未完成、阻塞点、关键文件、下一步。
3. 按「下一步动作」的第一条直接开工；遇阻塞点先看是否需要 Vange 拍板。
4. 遵守 agent.md v1.3 规范（模型守卫 Kimi K3、审查报告落盘、issue 库管理等）。

---

## 五、规则

- **一交接一文档**：每次交接只产生一份新文档，不覆盖旧文档（旧文档保留作历史审计）。
- **命名带日期**：`YYYY-MM-DD-交接-线程N.md`，方便按时间找最新。
- **字段不遗漏**：模板中的字段（已完成/未完成/阻塞点/关键文件/下一步）必须全部填写，保证新线程无需追问即可开工。
- **绝对路径**：关键文件一律写绝对路径，不写相对路径。
