# 轻量通道换 deepseek-v4-flash 评估（首字延迟 / 输出效果 / 回退）

- **查证方**：zcode（智谱 GLM）· 2026-08-18
- **对象**：BOX-3 快路径轻量通道现用 `deepseek-chat`（config.yaml `lightweight.model`），评估换 `deepseek-v4-flash`
- **方法**：同 key 同端点直连实测（api.deepseek.com），交错提问控制网络漂移；生产同款注入（SYSTEM_PROMPT + USER.md）
- **结论先行**：**可用、可回退，但默认形态不能直接换**——flash 默认先输出思考段，首正文 token 反而劣化（均值 +560ms、尖峰 6s）；关掉思考后延迟小优于 chat、质量持平。换不换是「成本/尾部稳定」取舍，**不是有效的首字延迟优化手段**。

---

## 一、可用性 ✅

- `deepseek-v4-flash` 在 api.deepseek.com 直连端点可用（HTTP 200），与 chat 同 key 同 base_url，无需动 .env/网络/红线。

## 二、首字延迟（核心发现：默认形态劣化，关思考后小幅占优）

### 2.1 默认 flash：思考段拖延正文（实测机制）

流式拆解（裸客户端，区分首 chunk / 首思考 / 首正文）：

| 模型 | 首个网络 chunk | 首思考 token | 首正文 token | 思考量 |
|---|---|---|---|---|
| deepseek-chat | 627~922ms | —（无思考） | 909~1347ms | 0 |
| deepseek-v4-flash | **256~280ms** | 820~825ms | 1135~2414ms | 135~534 字 |

flash 网络层其实更快（首 chunk 快 ~400ms），但**先流式输出思考段（reasoning_content），正文被思考时长拖延**；生产 `LightweightLLM.stream_chat` 只 yield 正文 delta，思考段会被静默吞掉——TTFT 实测：flash 默认 **avg 2320ms（尖峰 6029ms）vs chat 1100ms**，直接换 = 首字劣化，不可接受。

### 2.2 思考可关闭（参数实测）

| 关思考方式 | 效果 |
|---|---|
| `extra_body={'thinking': {'type': 'disabled'}}` | ✅ 思考 0 字（推荐） |
| `reasoning_effort: 'none'` | ✅ 思考 0 字 |
| `enable_thinking=False` / `reasoning.enabled=False` | ❌ 仍有 71~164 字思考 |

### 2.3 关思考后 TTFT 对比（8 问交错，生产同款注入）

| 指标 | deepseek-chat | flash（关思考） | 差 |
|---|---|---|---|
| ttft min / avg / P50 / max | 1431 / 1762 / 1616 / **2499** | 1468 / 1639 / 1650 / **1817** | avg **-123ms**，max **-682ms** |
| 整句 total avg | 2279ms | 2096ms | -183ms |

- 均值小幅占优（123ms，接近噪声），**尾部更稳**（max 差 ~0.7s，flash 分布更窄）。
- 注：本次会话整体网络慢于前日（前日 10 轮复测 chat 均值 825ms），绝对值不可跨日比较，交错对比的相对结论有效。
- 对 open_ms 的影响估算：约 -0.1~-0.2s（均值），波峰改善稍明显。

## 三、输出效果（5 问 + 多轮指代，逐条对照）

| 维度 | chat | flash（关思考） | 判定 |
|---|---|---|---|
| 人设（小V、口语、语气词） | ✅ 全部保持 | ✅ 全部保持 | 持平 |
| 健康数据兜底（心率未接入，不编造） | ✅ | ✅ | 持平 |
| 实时数据诚实（天气：明说查不了，指路 App） | ✅ | ✅ | 持平 |
| 能力自述（能做什么+边界） | ✅ | ✅ | 持平 |
| 多轮指代（「那你帮我查一下嘛」延续上下文） | ✅ | ✅ | 持平 |
| 断句标点纪律（语义转折用 。？！） | 大体遵守（偶用～连转折） | 大体遵守（偶用～连转折） | 持平（两者都非 100%，提示词约束对两个模型效力相同） |

代表性样本（「我现在心率多少呀」）：
- chat：「哈哈，我现在还没接入实时监测功能呢，等接通后再帮你看看哈～你先自己感觉一下，有没有心慌或者不舒服呀？」
- flash：「哈哈，我现在还看不到你的实时心率呢～这个功能还在准备中，等接入了我就能帮你看了。」

## 四、回退机制 ✅（有前提）

- **现状代码**：模型名只存在于 `config.yaml:22`（`lightweight.model`）+ `config.py:66` 默认值兜底 + 测试注入字符串——业务代码零耦合，warmup/心跳模型无关。
- **但注意**：当前 `LightweightLLM` 不传 `extra_body`，换 flash **必须改 llm.py**（加思考关闭参数）。若实现时把开关做成配置项（如 `lightweight.disable_thinking: true` 才发送），则：
  - 切换 = 改 yaml 两行（model + 开关）+ 重启；
  - **回退 = 改回 `deepseek-chat` + 开关置 false（或保留，不发送即无影响）+ 重启，零代码改动**，行为与现在完全一致。
- 判定：**可随时原样回退**，前提是 WB 实现时把思考开关做成配置而非写死。

## 五、综合建议

1. **不要为延迟而换**：关思考后收益仅 ~0.1-0.2s（均值），首字延迟的大头仍是 DeepSeek 服务端 TTFT 本身（前日复测均值 825ms，已判「接近下限」）；换 flash 不是有效的优化杠杆。
2. **若为成本/尾部稳定而换**（flash 档计价一般更低 + 波峰更稳）：可行，但**必须带思考关闭开关**，默认开启思考的 flash 对语音场景是负优化（均值 +0.6s、尖峰 6s）。
3. 决策建议交给 Vange：延迟维度无实质收益，成本维度需按官方定价核算（本报告未测计费，不下结论）。
