## 一、问题复述与根因

### 1.1 现象

同一事实「单车是 FACTOR OSTRO VAM」被记录 7 条，仅措辞不同：

```
用户的单车是FACTOR品牌
单车品牌是FACTOR，型号是OSTRO VAM（用户拼写为AUSTRA VAN AUSTRA，完整为FACTOR OSTRO VAM）
用户的单车是FACTOR OSTRO VAM型号
用户的单车是FACTOR，型号OSTRO VAM
用户拥有FACTOR OSTRO VAM自行车
用户骑车（拥有自行车）
用户的自行车是FACTOR OSTRO VAM
```

### 1.2 根因

`memory.py:60-62` 去重是**纯文本子串匹配**：

```python
for existing in facts:
    if fact in existing or existing in fact:
        return False
```

而 DeepSeek 每次提取措辞不同（品牌/型号/单车/自行车 混用、词序变化、夹带拼写备注），子串无法互相包含 → 去重失效。

**本质**：这是「语义重复」问题，子串匹配天然解决不了。

## 二、方案对比

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 归一化输出 | 提取 prompt 强制「类别: 主体: 属性值」结构，减少措辞差异 | 改动最小（只改 prompt） | DeepSeek 仍会措辞漂移，语义重复照样漏 | 不可靠，弃 |
| B 语义去重（关键词重叠度） | 提取时附带关键词集合，写入前按关键词重叠度判重 | 真正识别语义重复，稳健 | 需改存储格式/提取层 | **推荐** |
| C 提取时先查重 | 提取 prompt 喂入现有 user_facts.md 摘要，让 DeepSeek 判重输出 DUP | 语义判断最准 | 每轮多耗 token；user_facts 8KB 全喂入，成本高 | 备选 |

## 三、推荐方案 B：关键词重叠度语义去重

### 3.1 设计

**核心思路**：让 DeepSeek 在提取时**顺带输出该事实的关键词集合**，写入 `user_facts.md` 时按「关键词重叠度」判重——重叠度 > 阈值即视为同一事实，跳过或合并。

### 3.2 改动点

#### ① 存储格式扩展（memory.py）

`user_facts.md` 条目从三段改为四段，追加关键词（`|` 分隔，关键词间用 `,` 分隔）：

```
2026-08-20 | 物品 | 用户的单车是FACTOR OSTRO VAM | FACTOR,OSTRO,VAM,单车
```

- 兼容性：旧条目（三段）读取时按「无关键词」处理，判重时退回子串匹配兜底；
- 关键词去噪：英文品牌/型号保留原文，中文停用词（的/是/用户/我/有）过滤。

#### ② 提取层输出关键词（llm.py）

提取 prompt 的 REMEMBER 行格式改为：

```
REMEMBER: <类别>: <事实> ;; 关键词: k1,k2,k3
```

DeepSeek 输出后解析出 `事实` + `关键词`。关键词规则（写进 prompt）：
- 提取事实里的**专有名词**（品牌名、型号、人名、地名、机构名、具体数值）；
- 不含泛化词（单车/自行车 这类可归一化为「单车」作为一类关键词，但「拥有/骑车」这类动作不进关键词）。

#### ③ 去重逻辑（memory.py add_fact）

```python
def add_fact(self, category, fact, keywords=None):
    # 1. 子串匹配兜底（旧逻辑，处理旧条目/无关键词场景）
    # 2. 关键词重叠度：与现有条目逐个比较
    #    overlap = len(交集) / len(较小关键词集合)
    #    overlap >= 0.6 → 判重，跳过
    # 3. 都不命中 → 追加
```

- 阈值 0.6：同一事实通常关键词高度重叠（FACTOR/OSTRO/VAM 至少 2-3 个重合），不同事实（如「单车」vs「广东医科大学」）关键词几乎不重叠。
- 关键词数量少（1 个）时退化为子串匹配，避免误杀。

#### ④ remove_by_keyword 保持

遗忘指令仍按关键词做**包含匹配**（现有逻辑），不依赖新字段——「忘掉单车」能删掉所有含「单车」的条目。

### 3.3 边界情况

| 场景 | 处理 |
|---|---|
| 旧条目无关键词 | 退回子串匹配兜底，不误删 |
| 关键词只有 1 个 | 退化为子串匹配 |
| 同一主体属性更新（「单车是旧款」→「单车是捷安特」） | 关键词「单车」重叠但「旧款/捷安特」不同 → 重叠度低，不判重，两条并存（可接受：属性演进保留历史） |
| 事实完全重复但关键词措辞不同（单车/自行车） | 归一化：建立小同义词表（单车=自行车=脚踏车），或提取时统一用「单车」 |

### 3.4 改动文件与工作量

| 文件 | 改动 | 工作量 |
|---|---|---|
| `memory.py` | add_fact 加 keywords 参数 + 关键词重叠度判重 + 同义词归一 | 中（~40 行） |
| `llm.py` | 提取 prompt 加关键词输出要求 + 解析 `;; 关键词:` | 小（~15 行） |
| `tests/test_memory_auto.py` | 补去重用例（同事实不同措辞判重、不同事实不误杀） | 小 |

## 四、备选方案 C（提取时查重）

若方案 B 效果不理想，可退到方案 C：提取 prompt 附现有 user_facts.md 内容，让 DeepSeek 输出 `DUP: <已有事实关键词>` 表示重复。语义最准但每轮 token 成本高（8KB 全量注入），且 user_facts 越大越慢。**不作为首选，列为备选**。

---

## 五、验收标准

1. 同一事实用 3 种不同措辞告知（如「单车是捷安特」「我的是捷安特」「捷安特那辆」）→ 只记 1 条；
2. 不同事实（单车品牌 vs 学校名）→ 分别记 2 条，不误杀；
3. 旧数据兼容：现有 7 条重复的历史条目，改造后新写入不再增加重复；历史重复可留待人工清理或一次性迁移；
4. 遗忘「忘掉单车型号」仍能删掉所有单车相关条目（不受新字段影响）；
5. 单测覆盖：同义措辞判重、不同事实不误杀、关键词空退回子串匹配。
