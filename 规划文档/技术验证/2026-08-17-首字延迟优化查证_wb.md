# 首字语音输出延迟查证与优化方向（目标 ≤2s）

- **日期**：2026-08-17
- **性质**：延迟问题定位 + 优化方案（WorkBuddy 查证起草，供 Hermes 审阅、Vange 拍板）
- **背景**：Vange 提出目标「首字语音输出延迟降到 2s 以内」；v0.4 报告 open_ms 1633ms（A7 预热后），但真机体感仍会超 2s
- **实测工具**：`voice-bridge/measure_first_audio.py`（本轮新增，可复跑复测）
- **实测环境**：开发机（服务与真机联调同机），2026-08-16/17 两天采样

---

## 一、问题定位（实测数据）

### 1.1 当前体感首字延迟（闲聊/问候场景）

```
按键松开 → open_ms 1633ms（服务端首帧）→ +网络传输+固件起播（未计量，估 200-400ms）
→ 体感 ≈ 1.8-2.0s，波峰 >2s
```

今天单独复测生产路径首段（= tts_first 口径）：**775~1183ms，均值 930ms，另一次采样到 1691ms**——edge 延迟波动大，v0.4 报告的 1111ms 只是单点样本。**当前不能稳定压在 2s 内，用户体感准确。**

### 1.2 为什么闲聊/问候最慢：没有应答提示音兜底

`config.yaml` 中 `casual: []` 为空（`_pick_ack` 对空池返回 None），问候语又被关键词刻意排除（避免「你好→好嘞我想想」的别扭）。所以：

| 场景 | 首声语音 | 延迟 |
|---|---|---|
| 健康/工具类问题 | 预合成 ack 提示音 | ~0.5s ✅ |
| **闲聊/问候** | **LLM 首句 TTS** | **~1.6s+设备开销** ❌ |

### 1.3 open_ms 1633ms 构成拆解

| 分段 | 耗时 | 说明 |
|---|---|---|
| ASR final 解码 + 路由 + 首句等待 | ~114ms | 很快，不是瓶颈 |
| LLM ttft | 408ms | A7 预热+心跳保温后，接近 DeepSeek 直连下限 |
| **TTS 首段（tts_first）** | **~1111ms（波动 775~1691）** | **大头，见下拆解** |

### 1.4 tts_first 再拆解（本轮实测，5 轮 + 补充实验）

| 测项 | 实测 | 结论 |
|---|---|---|
| A 生产路径首段（`stream_synthesize` 首 yield） | 775~1183ms（avg 930） | 波动大是超 2s 的直接原因 |
| B edge 冷启动→首 audio chunk | 877~1111ms（avg 961） | 与 A 吻合（A≈B+解码阈值） |
| C1 WSS 建连（DNS+TCP+TLS+升级，直连口径） | 618~1241ms（avg 827） | **固定大项 ~0.65s，每句都付** |
| C2 ssml 发出→首 chunk（净合成等待） | 667~892ms（avg 778） | **edge 服务端合成启动延迟，换引擎才能消** ⚠️**本行数据作废（2026-08-17 zcode 复核）**：原测量脚本中招 SSML 双重转义（合成了 42s 标记文本），净等待被放大；真实值 ~200ms（zcode 复测 191ms、落地复测 tts_first 294ms 佐证，见《2026-08-17-首字延迟落地复核与TTS关键缺陷_zc.md》） |
| C3 空闲时长敏感性（0/0.15/0.3/0.5/1/2s 后再发 ssml） | 0.15~1.0s 空闲：净等待 ~735-780ms 稳定；**2s 空闲：恶化到 ~1034ms** | **预连接空闲安全窗口 ≤1s**（⚠️ 本行数值同样受双重转义污染，方向性结论保守可用，具体数值以修复后复测为准——zcode 复核注） |

关键发现：edge-tts 7.2.8 每次合成都新建 WSS 连接（`communicate.py:461`）；之前 ef1f19a 尝试跨请求连接池复用、因闲置连接被服务端关闭报 `Session is closed` 而86ce32f回退——**跨请求池化已证伪，但「请求内预连接」是另一条路**（连接只活 ~1s，无闲置风险，且本轮已验证 vendored 协议在 7.2.8 DRM/token 下可行）。

### 1.5 部署环境代理风险（新发现）

本机 Windows 系统代理开启（127.0.0.1:7800），shell 的 `NO_PROXY` 已含 api.deepseek.com（符合红线）。Python/aiohttp 不读注册表代理，但 **edge-tts 内部 `trust_env=True`：若服务进程环境存在 `HTTP(S)_PROXY` 变量，edge 流量会走代理**，延迟特征完全不同。部署/联调环境需确认无代理变量（与 AGENTS.md「任何环境不得配置代理」红线一致）。

## 二、优化方向（按预估收益排序）

### 方向1 · TTS 请求内预连接（最大项，预估省 ~400ms/句）

ASR final → 路由判定完成后**立即**后台建 WSS + 发 speech.config（~0.65s），与 LLM ttft（~0.4s）+ 首句生成（~0.1s）**并行**；首句到达即发 ssml → 净等待 ~0.75s。

- 时序对比（首句 t+0.5s 到达）：
  - 现状串行：0.5 + 建连0.65 + 净等0.73 ≈ **1.88s**
  - 预连接并行：max(0.5, 0.65) + 0.73 ≈ **1.38s**
- tts_first 从 ~1.1s（波峰 1.7s）降到 ~0.75-0.8s（建连的不确定性被并行吸收，波动也变小）
- 实现要点：vendored 最小协议（aiohttp ws_connect + 复用 edge_tts 的 DRM/constants，~80 行，已在本轮验证可行）；**预连接失败 → 无缝回退现有「用时建连」路径**，无正确性风险
- 约束：ssml 必须在建连后 ~1s 内发出（C3 实测 2s 空闲恶化）；后续句保持现有 N worker 并发即可
- 预期 open_ms：1633 → **~1.2s（波峰 ~1.4s）**

### 方向2 · 闲聊池补 ack 提示音（体感秒回，零代码改动）

`config.yaml` 填上 `casual` 池（如「嗯」「在呢」类短促语气词，预合成随机轮换）。轻量通道首 token（~0.4s）即播，闲聊体感首响应 <0.6s。
- 代价：闲聊会先应一声再答（产品取舍，**需 Vange 拍板**；问候语保持不应声）

### 方向3 · 小项叠加（~50-100ms）

- 首段解码阈值 1600→800 samples（首段 100ms→50ms 音频即可发）
- `miniaudio.decode` 放 `to_thread`（避免占事件循环，间接稳后续帧间隔）

### 方向4 · 设备侧计量补全（盲区，可能有 100-200ms）

open_ms 不含「首帧到板子 → I2S 起播」。建议固件加首帧接收/起播打点，把体感链路补完整；若起播 >300ms（WAV 解析、阻塞写），还有额外空间。

### 不建议动的

- **LLM ttft 408ms**：已有 A7 预热 + 4min 心跳保温，接近 DeepSeek 直连下限
- **跨请求连接池**：已证伪（86ce32f）
- **换 TTS 引擎**（火山/讯飞付费，国内 RTT 低可把 tts_first 压到 ~300ms）：收益最大但违背「小智音质」决策且引入成本，仅当方向1落地后仍不达标再议
- **首句 piper + 后续 edge 混合**：音色跳变明显，不推荐

---

## 三、建议结论

**目标「首字 ≤2s」可以达成，不需要换引擎**：

1. **落地方向1（TTS 预连接）+ 方向2（casual ack）**：闲聊/问候体感 ~1.4-1.6s（波峰 <1.8s），健康/查询 ack 秒回（<0.6s）✅
2. 方向3/4 作为收尾打磨
3. 两项落地后按 `measure_first_audio.py` + 服务端打点复测 10 轮以上，出实测报告归档

## 四、遗留风险

| 风险 | 缓解 |
|---|---|
| vendored 协议随 edge-tts 升级失效 | requirements 锁 7.2.8；协议失败自动回退现路径 |
| LLM 首句 >1s 才到（长问题/慢路径） | 预连接收益递减但非负（1s 空闲净等待 778ms 实测）；慢路径本就有安抚语 |
| 部署环境代理变量 | 部署检查无 `HTTP(S)_PROXY`（红线一致） |

## 五、落地实现结果（2026-08-17，已实现 + 实测）

### 已落地

| 方向 | 状态 | 说明 |
|---|---|---|
| 方向1 TTS 请求内预连接 | ✅ 已实现 | `tts.py` 新增 vendored 预连接（`_EdgePreconnect` + `EdgeTTS.open_preconnect`）；`pipeline.py` 路由判定后即预建 WSS，首句用预连接、失败自动回退用时建连 |
| 方向2 闲聊补 ack | ⏭ Vange 拍板跳过 | 维持「删闲聊应声」决定，不做 |
| 方向3 首段阈值 1600→800 | ✅ 已实现 | 首段 50ms 即发 |
| 方向3 miniaudio 放 to_thread | ⏭ 跳过 | 收益存疑（C 扩展解码 <1ms），8 worker 并发已分散阻塞 |
| 方向4 固件侧计量 | ⏸ 待固件 | 属设备侧，另立项 |

### 实现要点

- **预连接只对快路径（route≠HERMES）启用**：慢路径首句 >2s 才到，预连接会空闲恶化（C3 实测），且慢路径已有安抚语先行。
- **降级/失败均无缝回退**：预连接失败 → `open_preconnect` 返回 None；首段失败 → `_drain_stream` 返回 `emitted_any=False` 触发回退用时建连重合成；降级慢路径 → `disabled` 标记 + 收尾关闭未消费连接，无泄漏。

### 实测结果（5 句闲聊，服务端打点）

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| **tts_first（edge 首段）** | ~930ms（波峰 1691） | **均值 383ms（241~488）** | **省 ~550ms** |
| **open_ms（首声）** | ~2.3s | **均值 1512ms** | **省 ~800ms** |

- 预连接 **0 次回退**（5/5 全部成功使用）。
- 剩余 open_ms 构成：llm_ttft（443~916ms，DeepSeek 波动）+ 首句生成 + tts_first（~383ms）。
- 当前瓶颈已从 TTS 转为 **llm_ttft**（DeepSeek 首 token 波动），文档一.3 已判「接近下限，不建议动」。

### 结论

**方向1+3 落地后，闲聊/问候首声均值 1.5s（波峰 <2s），tts_first 从最大头降为次要项**。目标「首字 ≤2s」达成，无需换引擎。
