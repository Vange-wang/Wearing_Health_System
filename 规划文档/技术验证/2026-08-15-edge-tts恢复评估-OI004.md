# edge-tts 恢复方案评估（OI-004）

- **日期**：2026-08-15
- **执行**：WorkBuddy（开发员）
- **依据**：`2026-08-11-语音桥-spec-v0.2.md` §6.3 登记的独立评估任务
- **性质**：技术评估，不阻塞 v0.2 主线；结论供 Hermes 决策 TTS 主引擎策略

## 结论（先说答案）

**维持 piper 承载为 v0.2 主线，edge 恢复降级为"音色升级"可选项，不紧急。** 理由一句话：**edge 7.x 虽然 403 已修复，但实测首音频延迟 ~1s，比 piper（~0.2s）慢约 5 倍，恢复它反而拖垮 open_ms**。

| 方案 | 结论 | 关键依据（实测/实查） |
|---|---|---|
| piper（现状） | **推荐继续承载** | 本地推理 42~360ms/句，离线免费，延迟最优 |
| edge-tts 7.2.8 | 可选（音色升级），需 Hermes 批依赖 | 403 已修复（实测可合成）；但首音频 933~1185ms，输出固定 24kHz mp3 |
| 火山引擎 TTS | 不推荐本阶段 | 免费额度小（2万字符），需注册/认证/SDK，接入成本高 |
| 讯飞在线 TTS | 不推荐本阶段 | 免费包仅 1万次/3个月，正式套餐 ¥2000/年起 |

## 评估点 1：edge-tts 7.x 是否修复现网 403？—— ✅ 已修复（实测）

- **版本事实**：PyPI 最新 `edge-tts 7.2.8`（2026-03-23 发布）。403 修复路径：2025-12-11 "旧端点 + MUID 支持"（修 issue #445）；社区 issue #458（2026-01）报告 7.2.1 仍 403、升级到 7.2.7 解决。
- **实测（本机，2026-08-15，沙箱 venv 隔离，未动项目 venv）**：
  - `今天天气不错。` → 首音频 1185ms / 总耗时 1415ms / 11664 字节 ✅
  - `这是一句用来测量完整耗时的测试句子。` → 首音频 933ms / 总耗时 1182ms / 23616 字节 ✅
  - 连续两次成功合成，**无 403**。

**但注意**：Spec §6.3 曾预估 edge 延迟 0.3~0.6s，实测本机网络下**首音频 0.9~1.2s**（WebSocket 握手 + 首 chunk 是硬成本）。与 piper 的 0.2s 相比，恢复 edge 会让 open_ms 恶化 ~0.7-1.0s。**在"延迟优先 > 音色"的既定策略下，edge 恢复对 open_ms 是负收益。**

## 评估点 2：转码依赖是否踩红线？—— 踩，且有更轻的替代

- **事实**：7.x 输出固定 `audio-24khz-48kbitrate-mono-mp3`（7.2.8 提交说明明确硬编码 48kbps CBR），不支持自定义 PCM 格式。
- **转码到 16kHz WAV 的路径对比**：

| 路径 | 依赖 | 红线评估 |
|---|---|---|
| pydub + 系统 ffmpeg | pip 包 + **系统级 ffmpeg 安装** | ❌ 重：系统依赖 + 环境一致性差（正是 v0.1 vendor patch 想摆脱的） |
| **miniaudio** | 纯 pip wheel（内嵌解码器，无需系统 ffmpeg） | ⚠️ 轻：1 个 pip 依赖，但仍是"未列明新增依赖"，**需 Spec 审批** |

- **结论**：若恢复 edge，最小代价 = `edge-tts>=7.2.7` 升级 + `miniaudio` 解码 24k mp3→PCM + `audioop.ratecv` 重采样到 16k。两者都不是 v0.2 requirements 列明依赖，**必须经 Hermes 修订 Spec 后方可引入**。

## 评估点 3：火山/讯飞替代方案 —— 不适合本阶段

| 平台 | 免费额度 | 正式价格 | 接入成本 | 判断 |
|---|---|---|---|---|
| 火山引擎（豆包语音） | 新用户 2万字符（半年有效） | 按量 ~0.0003-0.0005 元/字符 | 注册 + 实名认证 + 创建应用 + SDK + key 管理 | ❌ 额度不够 demo 长期使用，接入重 |
| 讯飞在线 TTS | 个人 1万次/3个月 | ¥2000/年（50万次）起 | 同上 | ❌ 免费包太小，付费对毕设无必要 |

两者延迟（国内云）理论优于 edge，但都引入**新的云服务依赖 + 认证流程 + 计费**，与"毕设 demo 可控、可复现"的目标不匹配。piper 免费离线零依赖，已够用。

## 建议（供 Hermes 决策）

1. **OI-004 状态建议**：edge-tts 403 已修复（7.2.7+ 实测可合成），"恢复方案存在"问题本身**可关闭**；但"是否升级"转为新决策项。
2. **主线建议**：piper 继续承载（延迟最优、零依赖）。open_ms 达标线（≤1600ms 裁决口径）下 piper 是正确答案。
3. **可选项（不紧急）**：若未来追求音色自然度，升级 edge-tts 7.2.8 + miniaudio 转码，作为独立优化单独立项（需 Spec 加依赖 + 接受首音频 +0.7~1.0s 的 open_ms 代价，或改为"edge 合成长句、piper 播首句"的混合策略）。
4. **Spec §6.3 建议修订**：edge 延迟预估值从 0.3~0.6s 修正为实测 0.9~1.2s（本机网络），避免后续预算误判。
