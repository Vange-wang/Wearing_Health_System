# BLE 数据帧协议（P1 腕部节点 ↔ P2 BOX-3 central 契约）

- **起草**：zcode（开发员）· 2026-08-19
- **性质**：P1/P2 两端固件共同遵守的数据契约（BLE 立项 Spec §9 前置，依据预研 D3 草案 + Spec 决策 3/4/5 固化）
- **范围**：GATT 服务/特征定义、数据帧格式、采样与上报节奏、连接参数、断线重连语义

---

## 1. GATT 服务布局（NimBLE，连接模式）

| 服务 | UUID | 特征 | 属性 | 用途 |
|---|---|---|---|---|
| **心率（标准）** | `0x180D` | `0x2A37` Heart Rate Measurement | notify | 标准格式（兼容 nRF Connect 等工具调试），P1 调试用主通道 |
| **血氧+综合帧（自定义，主通道）** | `7a0b1000-8c1d-4e2f-9a3b-5c6d7e8f9a0b` | `7a0b1001-…`（同前缀+01） | notify | **BOX-3 生产用主数据通道**（8 字节综合帧，§2） |
| 设备信息（标准） | `0x180A` | `0x2A29` Manufacturer | read | 厂商串 "WearableHealth/1.0"（调试） |

- **为何双通道**：Spec 决策 4 要求心率走标准服务 0x180D（兼容性好）；血氧无标准服务走自定义。BOX-3 生产逻辑**只订阅自定义综合帧**（一帧含全部字段，解析单一）；标准心率服务保留给手机工具直连调试。
- MTU：帧仅 8 字节，**默认 MTU 23（20B 载荷）即可，无需 MTU 交换**（少一个协商环节）。

## 2. 综合数据帧（自定义特征 notify 载荷，8 字节，小端）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | seq | uint8 | 帧序号，+1 回绕；接收端用于丢帧检测 |
| 1 | flags | uint8 | bit0=HR 有效；bit1=SpO2 有效；bit2=运动伪影（本帧数据可能不准）；其余保留 0 |
| 2-3 | heart_rate | uint16 LE | BPM（0 表示无效，看 flags） |
| 4 | spo2 | uint8 | %（0 表示无效，看 flags） |
| 5 | confidence | uint8 | 算法置信度 0-100（<60 时置运动伪影位） |
| 6 | battery | uint8 | 电量 %（P1 USB 供电填 100/0xFF 未知） |
| 7 | reserved | uint8 | 保留 0（未来体温/ECG 扩展位） |

- 标准心率特征 0x2A37 按 Bluetooth SIG 格式：flags(1B, bit0=0 → uint8 BPM) + BPM(1B)，每次综合帧同时刷新。
- **无效值语义**：flags 位为 0 时对应字段忽略（传感器未就绪/伪影丢弃），BOX-3 不得把 0 当真实值缓存。

## 3. 采样与上报节奏（Spec 决策 5：周期采样）

```
[P1 指尖式 / USB 供电]  测量周期 5s：采 10s 窗口滑动平均 → 每周期 notify 1 帧
[腕部电池版（P5）]      测量周期 15s：LED 占空比 1/3，中间 light-sleep 保连接（届时调参）
```

- P1 按 **5s/帧**（Spec 决策 5），预警「连续 3 帧超阈值」≈15s 触发，满足家庭预警时效。
- 上报即当前最新值（滑动平均），无历史帧重传。

## 4. 连接参数与安全（预研 B3/B7 落地）

| 项 | 值 | 理由 |
|---|---|---|
| 连接间隔 | 100~200ms（peripheral 请求） | 5s 一帧，无需更密；省电 |
| 从机延迟 slave latency | 4 | 空闲期省电 |
| 监督超时 supervision timeout | 4s | |
| 配对 | Just Works，不加密 | 预研 B7 首期决策；数据不上云，风险可控 |
| 绑定 | 不绑定（bondless） | **BOX-3 侧 NVS 存对端 MAC**（预研 F1），直连重连 |

## 5. 广播与连接建立（P2 扫描匹配依据）

- 广播名：`WH-Wrist01`（可配）；广播含厂商自定义段（厂商 ID 0xFFFF + 2 字节能力位：bit0 心率、bit1 血氧），P2 扫描按名字前缀 `WH-` + 能力位匹配。
- 首次连接：BOX-3 按键触发扫描 → 连接成功 → NVS 存 MAC → 之后开机直连（预研 F1）。
- **断线重连**：BOX-3 侧检测断开 → 周期扫描指定 MAC → 重连（不阻塞语音任务）；腕部节点侧仅重新广播，等待 central 回连（F2）。

## 6. 丢帧与新鲜度（与 Spec §6 第 7 条衔接）

- BOX-3 按 seq 检测丢帧（回绕窗口内跳号），日志计数（F3）；BLE 连接模式链路层自带重传，丢帧罕见。
- BOX-3 → 服务端 POST `/api/v1/health/data` 失败时本地缓存最近 N=32 帧，恢复后批量补传（时间戳由 BOX-3 打）。
  - **补传帧格式**：在 8 字节综合帧外加 uint32 LE 毫秒时间戳（BOX-3 开机毫秒计数 + 已同步的服务端偏移），共 12 字节，仅用于 WiFi 上报，不进 BLE。

## 7. P1 验收挂钩

| Spec 用例 | 本契约对应点 |
|---|---|
| T1 指尖精度 ±3% | §2 字段/§3 滑动平均 |
| T2 BLE peripheral 广播+GATT | §1 服务布局/§5 广播名 |
| T3 BOX-3 central 收数据 | §2 帧解析（含无效值语义）/§4 连接参数 |
