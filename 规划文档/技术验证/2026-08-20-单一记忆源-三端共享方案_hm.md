# 单一记忆源方案：手机/电脑/BOX-3 三端共享记忆（修订版 v2）

- **起草**：Hermes（审查）· 2026-08-20 · 依据 Vange 拍板
- **修订**：v2（2026-08-20）——取消独立快速层文件，改为「共享记忆 + 6KB 注入窗口」；修复 v1 缺口（手机/电脑查不到快速层）
- **状态**：方案定稿（v1 的 quick_facts.md 独立文件设计废弃）
- **铁律**：① 三端共享同一份记忆 ② 任何改动不得牺牲首字输出延迟

## 一、目标与约束

| 目标 | 说明 |
|---|---|
| **三端共享** | 手机/电脑/微信/BOX-3 读写**同一份**记忆；任一端告知、**立即可见**于其他端；任一端遗忘、全端失效 |
| **首字延迟零牺牲** | BOX-3 首字路径（ASR→路由→注入→LLM 首 token）只读本地文件最近 6KB，绝无网络请求、注入量恒定 |

## 二、现状问题（已查证）

```
手机/电脑/微信 → Hermes（USER.md + MEMORY.md）
BOX-3 语音     → voice-bridge（user_facts.md 私有孤岛）❌ 不共享
```

- 英文名 Vange 双存（USER.md:11 + user_facts.md）→ 遗忘只删一边（真机复现）；
- user_facts.md 是 voice-bridge 私有文件，Hermes 不读、其他端不见 → 违背共享初衷；
- v1 方案（独立快速层 quick_facts.md + 归档）仍存在缺口：快速层内容在归档前手机/电脑不可见 → **v2 废弃该设计**。

## 三、目标架构（v2 定稿）：单一共享记忆 + 注入窗口

```
                 ┌─────────────────────────────────┐
手机 ────────────┤                                 │
电脑 ────────────┤  Hermes 记忆（唯一正本）          │
微信 ────────────┤  memories/USER.md（画像）        │
                 │  memories/MEMORY.md（事实，容量调大）│
BOX-3 语音 ─────►│  写入经 memory_server 接口         │
                 └─────────────────────────────────┘
```

**核心：记忆只有一份（Hermes 侧），不存在任何"另一个记忆文件"。**

- **BOX-3 注入**：从共享记忆**本地读取最近 6KB**（USER.md 全文 + MEMORY.md 最近部分）——量恒定、微秒级、不联网；
- **手机/电脑/微信注入**：Hermes 原有机制注入 USER.md + MEMORY.md **全量**（Hermes 侧 prefill 成本，与 BOX-3 首字无关）；
- **写入即共享**：语音提取的事实经 memory_server 直接写 MEMORY.md → 手机/电脑**立即可见**（无归档等待窗口）；
- **遗忘即全端失效**：删共享记忆对应条目（字段级）→ 所有端下次注入即无。

### 3.1 通道设计（首字约束检查）

| 通道 | 实现 | 首字影响 |
|---|---|---|
| **BOX-3 注入（读）** | 本地读 USER.md（全文，~2KB）+ MEMORY.md（最近部分，凑够 6KB 预算）——纯本地文件，微秒级 | ✅ 零影响（本地、量恒定 6KB） |
| **提取（写）** | 回复完成后后台线程调 `POST /api/v1/memory/fact` → Hermes 写 MEMORY.md（去重 + 容量裁剪） | ✅ 零影响（回复已播完，后台异步） |
| **遗忘（删）** | 后台线程调 `DELETE /api/v1/memory/fact?keyword=` → Hermes 字段级删 USER.md + MEMORY.md | ✅ 零影响（后台异步） |
| **手机/电脑查询** | Hermes 每轮注入 USER.md + MEMORY.md 全量 → 直接可见（无需慢通道！因为写入即共享） | 与 BOX-3 无关 |

> **首字红线**：BOX-3 注入 = 本地文件最近 6KB，量恒定，绝无网络请求。写入/遗忘全在回复完成后的后台线程。
> **慢通道不再需要**（v1 设计里"快速层查不到→慢通道查长期层"的场景消失——因为只有一份记忆，BOX-3 注入的就是全部记忆的最近 6KB 窗口，更早的记忆本就该被遗忘/裁剪）。

### 3.2 Hermes 侧新增（Hermes 实施）

**本地记忆服务 `~/.hermes/scripts/memory_server.py`（独立小服务，端口 8781）**：

```
GET    /api/v1/memory            → 返回 USER.md + MEMORY.md 合并内容（调试/对账用）
POST   /api/v1/memory/fact       {category, fact, keywords}   → 写入 MEMORY.md
DELETE /api/v1/memory/fact?keyword=X → 字段级删除 USER.md + MEMORY.md 匹配条目
```

实现要点：
1. **写入**：追加到 MEMORY.md（`§` 分隔条目，格式 `<日期> | <类别> | <事实> | 关键词1,关键词2`）；去重 = 关键词重叠度（交集/较小集，<3 个 0.8 / ≥3 个 0.6，延续任务 2 方案 B）；容量超限裁最旧（或归档到单独 archive 文件，可选）；
2. **字段级删除**：USER.md 按 `§` 分段、段内按 `字段: 值` 匹配删字段（只删 `English name: Vange. ` 保留同段名字/生日/电话）；MEMORY.md 按关键词删除整条；
3. **配置调优**：`hermes config set memory.memory_char_limit 8000`（MEMORY.md 从 2200 → 8000，容纳语音事实）；USER.md 保持 1375（画像字段少，不动）；
4. **安全**：仅监听 127.0.0.1；鉴权 token（与 API_SERVER_KEY 同源）；写操作校验类别白名单；删除需 keyword ≥2 字符。

## 四、验收标准

1. **三端共享（写入即见）**：语音告诉 BOX-3「我喜欢蓝色」→ **无需等待归档**，电脑/微信端问 Hermes「用户喜欢什么颜色」→ 立即答出；
2. **反向共享**：在 Hermes（电脑）端记忆「用户生日 2005.09.19」→ BOX-3 语音问「我生日什么时候」→ 答出（BOX-3 注入窗口含该条）；
3. **遗忘全端生效**：语音「忘掉我的英文名」→ USER.md 字段级删除（保留名字/生日/电话）+ MEMORY.md 删对应条目 → 电脑端 + BOX-3 端都答不出 Vange；
4. **首字延迟零劣化**：改造前后各测 10 次「你好」`llm_ttft`，均值差 ≤ +50ms；
5. **写路径不阻塞**：提取/遗忘期间语音回复正常（后台线程，无卡顿）；
6. **回归**：全量单测通过（原 60 + 新 memory 客户端用例）；去重/遗忘既有验收不回退。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| MEMORY.md 变大 → 手机/电脑 Hermes 注入变慢（非 BOX-3 首字） | memory_char_limit 8000 上限；Hermes 侧超限裁最旧；BOX-3 注入量恒定 6KB 不受影响 |
| memory_server 挂了 → 提取/遗忘失败 | 静默降级（不影响语音回复），日志记录；服务重启恢复；BOX-3 注入是本地读文件，**不受服务状态影响** |
| 字段级删除误伤 | 删除前 dry-run 返回待删内容；单测覆盖「段内删字段保留其他」 |
| 接口被未授权调用 | 仅 127.0.0.1 + 鉴权 token |
