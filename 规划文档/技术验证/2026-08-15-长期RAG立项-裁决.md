# 长期 RAG 立项裁决（轻量通道两项前置决策）

- **裁决方**：Hermes（deepseek-v4-pro）
- **日期**：2026-08-15
- **背景**：中期轻量直通查证不支持（Hermes 0.18.2 无 per-request 轻量开关、无预热复用），出路定为「跳长期 RAG = voice-bridge 自建轻量通道」。WorkBuddy 前置查证确认 Hermes built-in memory 为 markdown 文件（USER.md / MEMORY.md），可只读访问。本裁决定两项前置决策，长期 RAG 据此立项。

---

## 裁决① 注入范围：轻量通道只注入 USER.md，排除 MEMORY.md —— 同意

**裁决**：轻量通道（voice-bridge 自建）只注入 **USER.md**（用户身份 + 偏好），**排除 MEMORY.md**（技术笔记）。

**理由**：
- 语音对话需要「用户是谁 / 偏好什么」（USER.md），不需要「技术环境细节」（MEMORY.md：代理端口、编译坑、工具怪癖等）。
- 排除 MEMORY.md 减小 prompt、降延迟、减噪音——MEMORY.md 当前已近满（大量技术细节），对语音回答是纯噪音。
- 符合 Hermes memory 的 target 语义：`user` = 用户身份，`memory` = 操作笔记。

**附带约定**：语音场景相关的用户偏好记忆（如「用户喜欢 X」），后续统一约定存 **USER.md（target=user）**，避免误存 MEMORY.md 导致轻量通道漏读。

---

## 裁决② 裸模型来源：轻量通道恢复 DeepSeek，A1 语义修订为「分路」—— 同意

**裁决**：轻量通道用 **DeepSeek 裸模型直连**（v0.2 同款 deepseek-chat），A1 由「彻底停用 DeepSeek」修订为「分路」。

**A1 修订**：
- 旧：voice-bridge 彻底停用自带 DeepSeek，全量走 Hermes。
- 新：voice-bridge 分两路——
  - **轻量通道**：读 Hermes USER.md + DeepSeek 裸模型直连 → ~1.5s（纯闲聊 / 简单问答 / 知识库查询）
  - **慢路径**：完整 Hermes agent → ~3.5s（需技能 / 复杂工具，先安抚）

**理由**：
- 实测证明 Hermes agent 的 3.5s 是 per-request 固定成本（无轻量模式、无预热），裸模型是压回 1.5s 的唯一可行路径。
- 「共用记忆」的核心是**读同一份 memory 存储**（USER.md），不是「必须走 Hermes agent」。轻量通道读 USER.md，共用记忆依然成立。
- Hermes 内部模型本就是 DeepSeek，轻量通道用 DeepSeek 裸模型不违背「记忆共享」本意。

**红线不变**：轻量通道的 DeepSeek 裸模型**必须注入 USER.md**（否则退回 v0.2「无记忆裸聊」，共用记忆验收失效）。DEEPSEEK_API_KEY 保留，仅轻量通道引用；慢路径仍走 Hermes（不直连 DeepSeek）。

---

## 目标态路由（定稿）

```
用户语音 → ASR → 路由判定
              ├── 纯闲聊 / 简单问答 ──→ 轻量通道（DeepSeek 裸模型 + USER.md）──→ ~1.5s
              ├── 知识库查询 ──→ voice-bridge RAG 检索 + DeepSeek 裸模型 ──→ ~1.5s
              └── 需技能 / 复杂工具 ──→ 完整 Hermes agent（先安抚「我查一下」）──→ ~3.5s
```

路由判定原则：默认走轻量（快），命中技能 / 复杂工具需求才走慢路径。
