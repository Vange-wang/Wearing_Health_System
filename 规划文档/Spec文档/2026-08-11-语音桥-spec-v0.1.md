# 语音桥服务 Spec v0.1（2026-08-11）

> 本文档为 voice-bridge 服务的开发规格，WorkBuddy 按此实现。冲突时本文档优先于口头沟通。

## 1. 目标

在 PC 端提供一个本地 HTTP 语音服务：接收音频 → 语音识别(ASR) → 大模型回答(LLM) → 语音合成(TTS) → 返回音频。它是开发板（ESP32-S3）与 Hermes/DeepSeek 之间的语音通道（v0.1 暂不接 Hermes，直接调 DeepSeek API）。

## 2. 阶段边界

| 阶段 | 内容 | 验收 |
|---|---|---|
| v0.1（本文档） | 独立语音服务：ASR + DeepSeek(非流式) + TTS 整链路可跑 | 链路通、延迟可测、中文可用 |
| v0.2 | DeepSeek 流式 + 分句 TTS，开口延迟 ≤1.5s | 实测开口延迟 1.2~1.4s |
| v0.3 | 接入 Hermes 会话（共用记忆/技能），接口由 Hermes 定义 | 与微信共用记忆 |

**禁止**：v0.1 阶段不得实现流式、不得接 Hermes、不得引入未列出的依赖。

## 3. 技术栈（已敲定，不得更换）

- Python 3.11（解释器：`C:\Users\86166\AppData\Local\Programs\Python\Python311\python.exe`）

## 5. 接口定义

### GET /api/v1/health

返回 `{"status": "ok", "asr": "ready", "tts": "edge|piper"}`（启动时预加载模型并报告状态）。

### POST /api/v1/voice/chat

请求：`multipart/form-data`，字段 `audio` = WAV 音频（16kHz、16bit、单声道，≤15 秒）。

处理流程（每步打点计时，毫秒）：
1. ASR：sherpa-onnx + SenseVoice 识别为中文文本
2. LLM：调 DeepSeek（deepseek-chat），系统提示词见 §6
3. TTS：edge-tts 合成中文语音（失败自动切 piper）
4. 返回

响应：`application/octet-stream` 二进制 WAV（16kHz 16bit mono），响应头带计时信息：
`X-Timing: {"asr_ms":..., "llm_ms":..., "tts_ms":..., "total_ms":...}`

### 错误处理（完整错误码枚举）

| 场景 | 状态码 | 响应 |
|------|--------|------|
| ASR 失败 / 无有效语音 | 400 | `{"error": "no_speech"}` |
| 音频格式不合规（非 WAV / 非 16kHz / 非 mono） | 400 | `{"error": "bad_audio_format"}` |
| 音频超过 15 秒上限 | 413 | `{"error": "audio_too_long"}` |
| DeepSeek API key 未配置 / 配置缺失 | 500 | `{"error": "config_error", "detail": "..."}` |
| ASR 模型加载失败 / 服务未就绪 | 503 | `{"error": "service_unavailable"}` |
| LLM/TTS 上游失败 | 502 | `{"error": "upstream_error", "detail": "..."}` |

- 全链路日志：标准 logging，每个请求一条 `{"ts","asr_ms","llm_ms","tts_ms","total_ms","asr_text_len","tts_text_len"}`

## 6. LLM 系统提示词（v0.1 固定）

```
你是"小衡"，一个便携健康助手的语音助手。要求：
1. 回答简短口语化，一般不超过 50 字；能一句话说完就一句话。
2. 用户是通过语音对话，回复要像日常聊天，不要列点、不要 markdown。
3. 涉及健康数据的问题（心率/血氧/睡眠等）暂回答"健康数据监测功能即将上线"。
```

## 7. 配置（config.yaml）

```yaml
server:
  host: 0.0.0.0
  port: 8710
asr:
  model_dir: models/sherpa-onnx-sense-voice-zh
  sample_rate: 16000
tts:
  primary: edge
  edge_voice: zh-CN-XiaoxiaoNeural
  fallback: piper
llm:
  base_url: https://api.deepseek.com
  model: deepseek-chat
  api_key_env: DEEPSEEK_API_KEY
log:
  level: INFO
```

## 8. 模型获取（WorkBuddy 执行时下载）

ASR 模型：sherpa-onnx 官方 release 中的 `sherpa-onnx-sense-voice-zh-20240418.tar.bz2`（或仓库 scripts 里对应下载脚本），解压到 `voice-bridge/models/`。
参考：`https://github.com/k2-fsa/sherpa-onnx` 的 SenseVoice 文档（国内网络若 GitHub 慢，可用镜像或由 Hermes 协助）。

piper：`piper` Python 包 + 中文语音模型 `zh_CN-huayan-medium`（models 目录）。

## 9. 验收标准（v0.1 全过才算完成）

1. `GET /api/v1/health` 返回 ok，ASR/TTS 状态 ready
2. 用三句中文口语测试（本地录音 wav 或系统 TTS 生成）：
   - "今天天气怎么样"
   - "帮我查一下心率"
   - "你叫什么名字"
   每句返回语音可听懂、文字语义正确
3. `X-Timing` 头输出完整，各环节耗时在日志中可查
4. 断网场景：TTS 自动切换 piper 不崩溃（edge-tts 失败时日志有 fallback 记录）
5. 交付：源码 + requirements.txt + README(运行步骤) + 自测报告（三句实测 timing 数据，写入 `../Code文档/v0.1自测报告.md`）
6. 自动化冒烟测试（pytest，写入 `tests/` 目录）至少 4 条：
   - `GET /api/v1/health` 返回值格式校验
   - 空音频 → 400 `no_speech`
   - edge-tts 失败 → piper 兜底生效（fallback 日志可查）
   - `X-Timing` 响应头格式正确
   pytest 为 dev 依赖（不违反 v0.1 阶段边界），`requirements-dev.txt` 单独列出

## 10. 运行环境

- venv 创建在 `voice-bridge/venv`（Windows 下用 Python311 的 `python -m venv venv`）
- 启动：`venv\Scripts\python run.py`
- DeepSeek key：从 `~/.hermes/.env` 读取或复制到 `voice-bridge/.env`（不入库）
