## 1. 目标与范围

### 目标

在 ESP32-S3-BOX-3 到货后，验证选定开发环境（ESP-IDF 与 Arduino-ESP32 双路线）对 BOX-3 的板级支持（BSP）与工具链可用性，产出**选型结论 + 实测证据**，为固件开发铺路。验证通过 = 编译烧录跑通、外设全链路确认可达、工具链操作闭环。

### 非目标（本阶段不涉及）

- 不编写业务固件（录音/opus/WiFi 上传等），仅跑官方示例
- 不接入 Hermes / 语音桥服务
- 不做唤醒词/命令词 ESP-SR 训练（仅确认组件可编译可用）
- 不配置 ChatGPT / DeepSeek API key（chatgpt_demo 编译烧录即可，不真跑对话）

## 4. 双路线对比与选型结论判定

### 4.1 对比矩阵

| 维度 | ESP-IDF | Arduino-ESP32 | 胜负 |
|------|---------|---------------|------|
| 官方 BOX-3 支持 | ✅ 官方 BSP 组件，开箱即用 | ❌ 无官方 board 定义，需自行配置引脚 | IDF 大胜 |
| 官方示例覆盖 | ✅ factory_demo / chatgpt_demo 全链路（双麦+喇叭+屏幕） | ❌ 无 BOX-3 特定示例 | IDF 胜 |
| ES7210 / ES8311 驱动 | ✅ 官方 BSP 驱动，组件管理器自动拉取 | ❌ 需自行移植或裸写 I2S 驱动 | IDF 大胜 |
| ESP-SR（语音唤醒/命令词） | ✅ 官方组件，API 现成 | ❌ 几乎不支持 | IDF 胜 |
| LVGL GUI | ✅ 官方 box_demo 含 LVGL 整合 | ⚠️ LVGL 库可用但无 BOX-3 配好的 config | IDF 略胜 |
| 学习曲线 | 中（CMake + menuconfig + Kconfig） | 低（Arduino 风格） | Arduino 胜 |
| 维护性 / 量产 | 高（乐鑫主线，持续更新） | 中（社区维护） | IDF 胜 |
| 资料丰富度 | ESP-IDF 编程指南 + esp-box GitHub wiki | 社区论坛 / 零星教程 | IDF 胜 |
| PSRAM / Octal PSRAM | ✅ 原生支持，menuconfig 配置 | ⚠️ 需手动改 board 配置 | IDF 胜 |

### 4.2 判定标准

若 V-01~V-12 全部通过且 V-06（chatgpt_demo）无坑，则 IDF 是唯一合理选择。
若 Arduino 路线 V-A1~V-A4 有任意一项不通过且 IDF 路线通过，则直接锁定 IDF。

> 补充说明（2026-08-15 实测后修订）：示例代码自身的版本迁移坑（如 esp-box master 的 UI 停留在 LVGL8 时代，而 esp_lvgl_port v2 已升级 LVGL9，需移植适配）**不计入 IDF 路线缺陷**。「V-06 无坑」按「无 IDF 路线缺陷」实质判定。

### 4.3 推荐结论

**主推 ESP-IDF v5.2.7**。理由：官方 BOX-3 BSP 开箱即用，chatgpt_demo 已证明全链路可跑（屏幕 + 双麦 + 喇叭），ESP-SR 语音组件唯一支持路线。Arduino 路线无官方 BOX-3 board 定义，缺少 ES7210/ES8311 codec 驱动，毕设开发会陷入大量底层移植工作。

→ 验证报告 §6 需给出**正式选型结论**（一条判决句 + 引用 V-01~V-12 通过证据）。

## 7. 时间估算与依赖关系

### 7.1 时间估算

| 阶段 | 内容 | 预估耗时 | 前置条件 |
|------|------|----------|----------|
| 准备 | ESP-IDF 安装 + 环境配置 | 1~2h | 网络通畅，下载顺畅 |
| 准备 | Arduino 路线安装（可选） | 0.5h | — |
| 验证 1 | V-01~V-03（工具链 + BSP + LCD） | 1h | IDF 安装完成 |
| 验证 2 | V-04~V-06（音频 + 全链路） | 1.5h | V-02 通过 |
| 验证 3 | V-07~V-12（通信 + PSRAM + opus + BLE） | 1h | V-06 通过 |
| 验证 4 | V-A1~V-A4（Arduino 对比，可选） | 1h | Arduino 路线安装完成 |
| 报告 | 证据整理 + 报告撰写 | 1h | 全部验证项完成 |

**总计**：ESP-IDF 路线 4.5~5.5h（含安装）；双路线全跑约 6.5~7.5h。

> 以上估算不含网络下载等待时间（IDF 离线安装包约 2GB）。若遇 GitHub 下载组件慢，可使用国内镜像或由 Hermes 协助获取。

### 7.2 依赖链

```
V-01(IDF安装) ──→ V-02(BSP) ──→ V-03(LCD) ──→ V-04(录音)
                           │                    │
                           │                    └──→ V-05(播放)
                           │                         │
                           └──→ V-06(chatgpt_demo) ──┼──→ V-07(WiFi)
                                                     ├──→ V-08(PSRAM)
                                                     ├──→ V-09(opus)
                                                     ├──→ V-10(BLE)
                                                     ├──→ V-11(烧录链路)
                                                     └──→ V-12(ESP-SR)

V-A1(Arduino) ──→ V-A2(board) ──→ V-A3(LCD) ──→ V-A4(音频)
```

V-01 是整个验证的入口；V-06 是最核心的全链路验证项，通过后可并行执行 V-07~V-12。

### 7.3 已知风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| IDF 下载慢 | 中 | 延迟半天 | 离线安装包备用 |
| ESP-SR 编译报错 | 高 | 阻塞 V-12 | 删除 `.component_hash` 后重编（已知坑） |
| 组件管理器下载失败（GitHub） | 中 | 阻塞带外设的验证项 | 设置镜像或手动下载组件 |
