# 多 WiFi 自动切换 Spec

- **起草**：Hermes（deepseek-v4-pro）· 2026-08-18
- **依据**：Vange 拍板三项决策（预置三组 / v2 优先 / 开关机扫描）
- **实施**：WorkBuddy（固件 voice_agent.c）

---

## 1. 目标

设备记住多组 WiFi 凭据，在不同网络环境（家里 / 学校 / 手机热点）间自动切换：开机扫描连接、断开自动重连，连上后 mDNS 自动广播、语音链路（含 TTS）自动恢复。为「出门随身」做网络层准备。

## 2. 需求（Vange 已拍板）

1. **预置三组 WiFi**：2702（家里）、L1122S（学校）、v2（iPhone 热点），NVS 存储不硬编码。
2. **连接优先级**：**v2 热点优先**（在则连 v2），其余「自己的 WiFi」为主（2702 → L1122S 顺序）。
3. **扫描时机**：**开关机时扫描**（开机扫一次连接；运行中不周期扫描省电）。
4. **后续扩展**：校园网（网页认证，非简单密码）之后再说——本次不做，但存储结构预留扩展位。

## 3. 方案

### 3.1 WiFi 凭据存储（NVS）

| 索引 | SSID | 密码 | 优先级 |
|---|---|---|---|
| 0 | v2 | (iPhone 热点密码) | **1（最高）** |
| 1 | 2702 | (家里密码) | 2 |
| 2 | L1122S | (学校密码) | 3 |

- 存 NVS（`wifi_count` + 每组 `ssid`/`pass`/`prio`），非硬编码，改网络/加网络不重烧固件。
- 预留扩展：结构支持「auth_type」字段（本次全 WPA2-PSK，未来校园网网页认证填 portal）。

### 3.2 自动连接逻辑

1. **开机扫描连接**：`esp_wifi_scan` 扫描可用 AP → 匹配 NVS 凭据（SSID 相同）→ 按 **prio 升序**（v2 最优先），同 prio 按 RSSI 信号强度降序 → 连接第一个可用的。
2. **断开自动重连**：`WIFI_EVENT_STA_DISCONNECTED` 触发 → 重新扫描匹配 → 连接下一个可用（不是死等当前 AP）。
3. **粘性**：已连接则保持，不主动切换（信号波动不来回跳）；只有断开才重新扫描切换。
4. **不周期扫描**（省电，配合未来低功耗休眠）。

### 3.3 链路自动恢复（串联已有能力）

WiFi 连上 → 触发 mDNS 广播（已做）→ `voicebridge.local` 解析 → 语音链路恢复 → TTS（edge-tts IPv4 已修）正常。

## 4. 关键决策（已对齐）

| # | 决策点 | 裁决 |
|---|---|---|
| 1 | 配置方式 | 预置三组 NVS（编译/首次写入）；校园网网页认证之后再说，结构预留扩展 |
| 2 | 连接优先级 | v2 最优先（1）；2702（2）→ L1122S（3） |
| 3 | 扫描时机 | 开关机扫描 + 断开事件重连；不周期扫描 |

## 5. 验收标准

1. 开机扫描 → 按优先级连接（v2 在则连 v2，否则 2702，再 L1122S）。
2. 当前 WiFi 断开 → 自动重连到下一个可用（日志记录切换）。
3. 切换后 mDNS 广播更新、语音链路恢复（voicebridge.local 解析 + 端到端对话）。
4. 三组 WiFi 场景实测：家里 2702 / 学校 L1122S / 热点 v2 各能连、能切换。
5. NVS 存储持久：重启后凭据仍在，无需重配。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| ESP32-S3 只支持 2.4GHz（坑1） | 扫描匹配天然只认 2.4G；5G 热点需开兼容 |
| 扫描与连接不能并行（WiFi 分时） | 逻辑串行：扫完 → 停扫描 → 连接 |
| 多 AP 同 SSID（如两个「v2」） | 同 SSID 按 RSSI 选最强 BSSID |
| 断开重连抖动（信号边缘来回切） | 粘性连接 + 重连退避（连续失败指数退避） |
| 校园网网页认证（未来） | 本次不做，结构预留 auth_type 字段 |
