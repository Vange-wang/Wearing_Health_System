# 语音桥 v0.4 Spec（真机固件联调）正式版

> 本文档为 voice-bridge v0.4 开发规格。继承 v0.1~v0.3 与长期 RAG 全部架构约束。
> 冲突时本 Spec 优先。WorkBuddy 按此实现。
> 起草 + 修订：Hermes（deepseek-v4-pro）· 2026-08-16
> **决策记录**：A1~A4 已拍板（见 §5）。A2 增量 ASR 直接做；A1 经查证由 opus 改 raw PCM（见 `2026-08-16-v0.4-A1A2查证-裁决报告.md`）。

---

## 1. 目标

把 voice-bridge 从「PC 侧服务」扩展为「真机语音终端」：ESP32-S3-BOX-3 固件实现录音 → 流式上传 PCM → 接收帧 → 解码播放的全链路，与 voice-bridge 服务端打通，验证**真机端到端延迟**。

- **固件侧**：BOX-3 按键录音（ES7210）→ 边录边流式上传 PCM → 接收长度前缀帧 → 解码播放（ES8311）。
- **服务端侧**：接收 PCM 流 → **增量 ASR（流式识别）** → 路由 → LLM → TTS 分句 → 返回长度前缀 WAV 帧。
- **增量 ASR（A2）**：边录边识别，按键松开识别结果即就绪。

**一句话**：M0 验证了「硬件都通」，v0.4 串成「能对话的真机」，识别走流式、传输走 raw PCM（局域网零依赖）。

- 唤醒方式 v0.4 只用**按键触发**（A3），不做唤醒词。

## 3. 架构

```
ESP32-S3-BOX-3（固件）                          PC（voice-bridge 服务端）
─────────────────────                          ─────────────────────────
按键按住 → ES7210 录音(16k/16bit/mono PCM)
         → 边录边流式上传 PCM 分块（HTTP chunked）
         → 按键松开 → 流结束（结束信号）──────→ 流式 ASR（zipformer，partial 持续更新）
                                                  → final result → 路由（轻量/RAG/Hermes）
                                                  → LLM → TTS 分句
         ← 接收长度前缀 WAV 帧 ←──────────────── ← 长度前缀帧编码
         → 逐帧解码播放(ES8311)
```

- 录音采样率 **16kHz**（与服务端 ASR 一致，避免重采样）。
- 端点检测 = **按键松开**（A3 按键触发，天然结束信号，禁用流式 ASR 的静音端点检测）。
- **A1 raw PCM**：局域网 16k/16bit/mono PCM = 32KB/s，带宽可忽略，零编解码依赖（opus 广域网优化登记 ISSUE-0006）。
- 服务端现有流水线（含长期 RAG 三层路由）不变，只把 ASR 换流式。

## 4. 组件改动

### 固件侧（D:\esp-box，ESP-IDF v5.2.7）

| 模块 | 来源 | v0.4 工作 |
|---|---|---|
| 录音 | ES7210（M0 V-04 已验证） | 集成，PCM 16k/16bit/mono |
| 流式上传 | WiFi（M0 V-07 已验证） | HTTP chunked，边录边发 PCM 分块（如 100ms 一块），按键松开结束流 |
| 帧解析 | 长度前缀帧（v0.2 定义） | ESP32 端实现：读 4 字节长度 → 读 N 字节 → 播放 |
| 播放 | ES8311（M0 V-05 已验证） | 逐帧解码播放 |

（**无 opus 编码**——A1 raw PCM，固件免编码。esp-opus 组件留待广域网 ISSUE-0006。）

### 服务端侧（voice-bridge）

| 模块 | v0.4 工作 |
|---|---|
| ASR 换流式（A2） | sherpa-onnx 批式 SenseVoice → 流式 zipformer（`streaming-zipformer-bilingual-zh-en`），加流式 feed + partial/final 回调；**无新增依赖**（sherpa-onnx 已内置） |
| 接收端 | 流式接收 PCM（HTTP chunked），结束信号 = 流关闭 |
| 现有流水线 | 不变（路由/LLM/TTS/分帧） |

（**无 opus 解码层**——raw PCM 直进 ASR。）

| 编号 | 决策项 | 裁决 |

## 6. 验收标准（v0.4 全过才算完成）

1. 真机端到端链路通：按键说话 → 固件录音 → PCM 流式上传 → 服务端流式识别 → 返回帧 → 固件播放出声音（人耳可确认）。
2. 流式 ASR 生效（A2）：边录边识别，partial result 持续更新，按键松开后 final result 就绪（无需等整段批式识别）。
3. ESP32 帧解析正确：长度前缀帧逐帧解码播放，无串帧/丢帧。
4. 服务端流水线不回退：轻量通道延迟、知识库 RAG、慢路径安抚语回归通过（沿用长期 RAG 验收）。
5. 真机端到端延迟实测数据记录（A4 目标线，实测后定）。
6. 错误路径：WiFi 断开 / 服务端不可达 → 固件不崩、可重连。
7. 结构化日志：固件侧 + 服务端侧均可观测（录音字节数、PCM 分块数、partial/final 结果）。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 流式 zipformer 准确率低于 SenseVoice | 识别率略降 | 对按键短指令够用；准确率实测后评估是否接受 |
| 流式模型 ~240MB 下载 | 依赖外部网络 | hf-mirror 直连或 Clash 代理，Vange 配合 |
| ESP32 帧解析串帧/丢帧 | 播放乱 | 8MB 守卫 + 逐帧校验 + 实测 |
| WiFi 断连 | 链路中断 | T6 重连机制 |
| raw PCM 广域网带宽 | 远程访问时 32KB/s 偏大 | 登记 ISSUE-0006（opus 广域网优化），局域网无碍 |
