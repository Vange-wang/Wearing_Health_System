# 语音桥 v0.4 Spec（真机固件联调 + 体验优化）正式版

> 本文档为 voice-bridge v0.4 开发规格。继承 v0.1~v0.3 与长期 RAG 全部架构约束。
> 冲突时本 Spec 优先。WorkBuddy 按此实现。
> 起草 + 修订：Hermes（deepseek-v4-pro）· 2026-08-16
> **决策记录**：A1~A6 已拍板（见 §5）。A1 opus→raw PCM；A2 增量 ASR 换流式模型；A5 TTS 换 edge-tts；A6 间隔优化。

---

## 1. 目标

把 voice-bridge 从「PC 侧服务」扩展为「真机语音终端」，并补齐「自然对话体验」：

- **固件侧**：BOX-3 按键录音（ES7210）→ 边录边流式上传 PCM → 接收长度前缀帧 → 解码播放（ES8311）。
- **服务端侧**：接收 PCM 流 → **增量 ASR（流式）** → 路由 → LLM → **edge-tts 分句合成** → 返回长度前缀 WAV 帧。
- **自然体验（A5/A6）**：TTS 换 edge-tts（发音标准）；句间 300ms 停顿 + 小数点消歧（间隔自然）。

**一句话**：M0 验证了硬件，v0.4 串成真机，且「发音标准 + 间隔自然」。

**禁止（红线）**：
- 服务端流水线契约不变（PCM 16k/16bit/mono 进 ASR——raw PCM 天然满足）。
- 不改帧协议（长度前缀 16k/16bit/mono WAV）。
- 唤醒方式 v0.4 只用**按键触发**（A3）。
- **新增依赖仅限 `miniaudio`**（A5 edge-tts 解码 24k mp3 用，纯 pip wheel 内嵌解码器，经 Vange 拍板审批）。

## 3. 架构

```
ESP32-S3-BOX-3（固件）                          PC（voice-bridge 服务端）
─────────────────────                          ─────────────────────────
按键按住 → ES7210 录音(16k/16bit/mono PCM)
         → 边录边流式上传 PCM 分块（HTTP chunked）
         → 按键松开 → 流结束（结束信号）──────→ 流式 ASR（zipformer，partial 持续更新）
                                                  → final result → 路由（轻量/RAG/Hermes）
                                                  → LLM 流式 → 分句（小数点消歧）
                                                  → edge-tts 逐句合成（24k mp3→16k WAV）
                                                  → 句间 300ms 停顿 → 长度前缀帧发送
         ← 接收长度前缀 WAV 帧 ←──────────────── ← 逐帧
         → 逐帧解码播放(ES8311)
```

- 录音采样率 16kHz；TTS 输出 16kHz（edge 24k mp3 转 16k WAV，帧协议不变）。
- 端点检测 = 按键松开（禁用流式 ASR 静音端点检测）。
- 句间 300ms 停顿在**服务端 pipeline** 发送层实现（发完一句的帧停 300ms 再发下一句）。

### 固件侧（D:\esp-box，ESP-IDF v5.2.7）

| 模块 | 来源 | v0.4 工作 |

| 录音 | ES7210（M0 V-04 已验证） | 集成，PCM 16k/16bit/mono |

### 服务端侧（voice-bridge）

| 模块 | v0.4 工作 |
|---|---|
| ASR 换流式（A2） | sherpa-onnx 批式 SenseVoice → 流式 zipformer，加流式 feed + partial/final 回调；无新增依赖 |
| 接收端 | 流式接收 PCM（HTTP chunked），结束 = 流关闭 |
| **TTS 换 edge-tts（A5）** | edge-tts 升级 7.2.8（修复 403）；合成输出 24k mp3 → **miniaudio** 解码 → audioop.ratecv 重采样 16k → WAV；piper 保留兜底（edge 故障时切 piper） |
| **间隔优化（A6）** | splitter.py 加小数点消歧（数字+小数点不拆句）；pipeline.py 句间 300ms 停顿 |
| 现有流水线 | 路由/LLM/分帧不变 |

## 6. 验收标准（v0.4 全过才算完成）

1. 真机端到端链路通：按键说话 → 录音 → PCM 流式上传 → 流式识别 → 返回帧 → 播放出声音（人耳可确认）。
2. 流式 ASR 生效（A2）：边录边识别，按键松开后 final result 就绪。
3. ESP32 帧解析正确：长度前缀帧逐帧解码播放，无串帧/丢帧。
4. **TTS 换 edge 生效（A5）**：health 上报 active_engine=edge（非 piper），发音自然、多音字正确。
5. **间隔自然（A6）**：句间 300ms 停顿可感知；含小数点的句子不被误拆。
6. 服务端流水线不回退：轻量通道、知识库 RAG、慢路径安抚语回归通过。
7. 真机端到端延迟实测数据记录（A4，含 edge 首音频代价）。
8. 错误路径：WiFi 断开 / 服务端不可达 → 固件不崩、可重连；edge 故障 → piper 兜底不崩。
9. 结构化日志：固件侧 + 服务端侧可观测（PCM 分块数、partial/final、edge/piper 引擎、句间停顿）。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 流式 zipformer 准确率低于 SenseVoice | 识别率略降 | 对按键短指令够用；实测评估 |
| 流式模型 ~240MB 下载 | 依赖外部网络 | hf-mirror 直连或 Clash 代理，Vange 配合 |
| edge-tts 首音频 0.9-1.2s | 首句延迟增加 | 已拍板接受（A5）；真机 A4 延迟线放宽；piper 兜底 |
| edge 7.x 转码链路（mp3→16k WAV） | 引入 miniaudio 依赖 + 转码耗时 | 依赖已审批；转码耗时实测 |
| ESP32 帧解析串帧/丢帧 | 播放乱 | 8MB 守卫 + 逐帧校验 + 实测 |
| WiFi 断连 | 链路中断 | T8 重连机制 |
| raw PCM 广域网带宽 | 远程访问偏大 | 登记 ISSUE-0006 |
