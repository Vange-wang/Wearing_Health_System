# 句间连读修复 Spec

- **依据**：`2026-08-17-句间连读问题查证_zc.md` + `2026-08-17-句间连读问题-审查确认.md`
- **范围**：本次修 #1#2#3（治本+治标+防腰斩）；#4（语义分级停顿）登记后续，不阻塞本次

## 1. 目标

修复「两个不同语义的句子之间间隔短/连读」问题：语义转折处能正确分句，分句处有正常断句停顿（≥0.6s），句内逗号保持连贯。

## 2. 根因（已查证）

1. **主因**：人设提示词下 LLM 几乎不用句号（4 问实测句号 0 次），语义转折靠逗号/波浪号串联 → 整段一次 TTS 合成 → 转折处仅 edge 逗号自然停顿 157~306ms → 连读感。
2. **字符 bug**：分句集波浪号是 `〜`(U+301C)，LLM 输出 `～`(U+FF5E)，码位不匹配 → 本应分句不拆 + 50 字兜底词中腰斩（「那|些」）。
3. **次因（本次不做）**：无语义分级停顿（话题切换 vs 普通句间统一 300ms）——登记后续。

## 3. 修改项

### 3.1 提示词约束（#1，治本）— `app/llm.py` SYSTEM_PROMPT

在「说话风格」部分加一条（注意：**只约束语义转折，保留口语化**）：

> 语义转折、话题切换必须用句号（。）或问号（？）或叹号（！）断开，禁止一逗到底；同一话题内的句子可用语气词、波浪号（～）自然衔接。

实现：在原 SYSTEM_PROMPT 的说话风格段追加一行约束，不删除现有口语化要求。

### 3.2 分句集补字符（#2，治标）— `app/splitter.py`

- `_SENTENCE_PUNCT` 补 `～`(U+FF5E)——**必加**（LLM 实际输出的全角波浪号）。
- 评估 `…`(U+2026)、`—`(U+2014)：若 LLM 输出中这些符号常出现在语义边界（实测判断）则加；若可能误拆（如破折号引出解释性内容）则不加。WorkBuddy 用真实回复样本实测后决定。

### 3.3 兜底拆分对齐边界（#3，防腰斩）— `app/splitter.py`

`max_chars` 兜底拆分时，优先在**最近的可接受边界**（逗号、顿号、空格）处断，不再任意位置硬切；找不到任何边界才硬切（并留日志）。防「那|些」类词中腰斩。

## 4. 不做（后续）

- **语义分级停顿（#4）**：话题切换标点 → 更长停顿（~600ms）。需分句器输出边界类型 + pipeline 发帧间隔分级 + 帧协议扩展，中成本。登记后续 issue，不进本次。

## 5. 验收标准

1. 「你都能做什么呀」复测：回复拆出 **≥2 句**、拆点落在语义边界、**无词中腰斩**。
2. 听感：语义转折句间停顿 ≥0.6s；句内逗号仍连贯（157~306ms 自然停顿）。
3. 口语化不退化：回复仍带语气词/波浪号（同一话题内），不是书面语腔。
