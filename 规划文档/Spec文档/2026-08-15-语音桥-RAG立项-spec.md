# 语音桥长期 RAG 立项 Spec（正式版）

> 本文档为 voice-bridge 长期 RAG 开发规格。继承 v0.1~v0.3 全部架构约束。
> 冲突时本 Spec 优先。WorkBuddy 按此实现。
> 起草：Hermes（deepseek-v4-pro）· 2026-08-15
> **决策记录**：A1~A4 已于 2026-08-15 拍板（Vange 定 A1/A2，Hermes 定 A3/A4，见 §5），本版为正式 Spec。

---

## 1. 目标

在 v0.3（接入 Hermes，3.5s 延迟）基础上，加「轻量通道 + 知识库 RAG」，把纯闲聊 / 简单问答 / 知识库查询的开口延迟压回 ~1.5s，同时保留「共用记忆」与「技能」能力。

- **轻量通道**：voice-bridge 读 Hermes USER.md + DeepSeek 裸模型直连 → ~1.5s（纯闲聊/简单问答）。
- **知识库 RAG**：voice-bridge 内置 BM25 检索 + DeepSeek 裸模型 → ~1.5s（知识库查询）。
- **慢路径**：完整 Hermes agent → ~3.5s（需技能/复杂工具，先安抚，v0.3 已实现）。

**核心目标**：延迟治理（3.5s → 1.5s），共用记忆与技能能力不回退。

---

## 2. 阶段边界

| 阶段 | 内容 | 验收 |
|---|---|---|
| v0.3（已完成） | 接入 Hermes + 共用记忆 + 安抚语 | ✅ REVIEW_CONDITIONAL_PASS |
| **长期 RAG（本文档）** | **轻量通道 + 知识库 RAG，延迟回 ~1.5s** | 纯闲聊 open_ms 稳态 ≤2000ms；知识库查询命中 |
| v0.4 / M1（后续） | 真机固件联调：opus 线协议 + ESP32 帧解析 + 增量 ASR | 真机端到端延迟 |

**禁止（红线）**：
- 不改 ASR 引擎、不改 TTS 主从、不改帧协议（延续 v0.1~v0.3）。
- 轻量通道的 DeepSeek **必须注入 USER.md**（否则退回 v0.2 无记忆裸聊，共用记忆验收失效）。
- 慢路径仍走完整 Hermes agent，**不得**直连 DeepSeek（技能/复杂工具只在 Hermes 侧）。
- **新增依赖仅限 `jieba`**（纯 Python，分词用），其余一律不引入（onnxruntime/bge 等语义增强留后续单独立项，不进入本次）。

## 3. 架构（三层路由）

```
用户语音 → ASR → 路由判定（router，A2 规则）
              ├── 纯闲聊 / 简单问答 ──→ 轻量通道（DeepSeek 裸模型 + USER.md）──→ ~1.5s
              ├── 知识库查询 ──→ BM25 检索 + DeepSeek 裸模型 ──→ ~1.5s
              └── 需技能 / 复杂工具 ──→ 完整 Hermes agent（先安抚「我查一下」）──→ ~3.5s
```

**路由判定规则（A2，定稿）**：

```
1. 命中「技能触发词/工具需求」→ 慢路径（完整 Hermes agent + 安抚语）
   含：明确命令类（查快递/写文件/发邮件/定时/搜网页）、已注册 skill 名/触发词
   （技能触发词清单由 WorkBuddy 从 Hermes 已装 skills 抽取维护）
2. 命中「知识库索引」（BM25 top-k 命中且分数超阈值）→ RAG 通道（DeepSeek + 检索结果）
3. 其余（纯闲聊/简单问答）→ 轻量通道（DeepSeek + USER.md）
4. 兜底：轻量通道 DeepSeek 失败/超时 → 降级慢路径（Hermes）不崩
```

- **共用记忆**：轻量通道读 Hermes USER.md（同一份存储），与微信共享；慢路径走 Hermes agent 自然共享。
- **知识库**：voice-bridge 本地 BM25 索引，检索结果注入 DeepSeek prompt。

## 4. 组件改动（voice-bridge/）

| 组件 | v0.3 | 长期 RAG 改动 |
|---|---|---|
| `app/llm.py` | 只走 Hermes API Server | 加「轻量通道」路径：DeepSeek 裸模型（base_url=api.deepseek.com，model=deepseek-chat）+ USER.md 注入；Hermes 路径保留为慢路径 |
| `app/router.py`（新增） | 无 | 路由判定：按 §3 四步规则分三类 |
| `app/rag.py`（新增） | 无 | BM25 检索（jieba 分词 + rank_bm25 自研/轻实现），numpy 暴力打分，top-k 召回 |
| `app/knowledge.py`（新增） | 无 | 知识库加载：扫描 `knowledge/*.md` 建索引；`POST /api/v1/knowledge/reload` 热重载 |
| `app/pipeline.py` | ASR→LLM→分句→TTS→帧 | 加路由分发 + RAG 注入分支；安抚语复用（慢路径） |
| `app/config.yaml` | llm→hermes 段 | 加 lightweight（deepseek）+ rag（knowledge 目录/阈值/top-k）+ router 段 |

**USER.md 只读注入**：轻量通道每次请求读 Hermes USER.md（文件路径 WorkBuddy 前置定位，已确认可只读访问），注入 DeepSeek system prompt；不读 MEMORY.md（裁决①）。

**知识库数据源（A1）**：健康科普 FAQ——初期 `knowledge/` 放 2~3 条占位健康知识（心率正常范围 60~100 次/分、血氧正常 ≥95% 等）跑通链路，真实内容后补。

## 6. 验收标准

1. 纯闲聊走轻量通道：`llm.py` 请求打到 DeepSeek（非 Hermes），open_ms 稳态 ≤2000ms（含 USER.md 注入开销）。
2. 轻量通道共用记忆：轻量通道读到 Hermes USER.md，微信写入的用户偏好能被语音轻量通道答出。
3. 知识库查询：命中知识库文档时，回答含检索到的内容（BM25 RAG 生效）。
4. 慢路径不回退：需技能/复杂工具仍走完整 Hermes agent，先发安抚语（v0.3 已实现，回归验证）。
5. 路由正确：纯闲聊走轻量、技能触发走慢路径、知识库查询走 RAG，分类准确（抽样验证）。
6. 错误路径：DeepSeek 不可达 → 502 upstream_error；USER.md 读取失败 → 降级慢路径或报错，不崩。
7. 知识库热重载：`POST /api/v1/knowledge/reload` 后新知识生效，无需重启服务。
8. 结构化日志：记录 route=lightweight/rag/hermes + open_ms + 不记语音正文。

## 9. 风险与缓解
