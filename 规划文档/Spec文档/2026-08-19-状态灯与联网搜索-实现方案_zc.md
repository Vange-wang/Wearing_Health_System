## 需求 1：屏幕 emoji 状态显示（Vange 拍板 2026-08-20，替代原状态灯方案）

### 1.1 需求原文（Vange）

原状态灯方案搁置（灯2 GPIO 未定位 + MCLK/GPIO2 复用冲突）。**改为用 BOX-3 屏幕背光显示状态 emoji**：

- **首选 4 态**：
  | 状态 | emoji |
  |---|---|
  | voicebridge 可用 + WiFi 可用 | 大笑 😄 |
  | voicebridge 可用 + WiFi 不可用 | 晕乎乎 😵 |
  | voicebridge 不可用 + WiFi 正常 | 闭嘴 🤐 |
  | 两个都不行 | 黑脸 🌚 |
- **退步 2 态**（若 4 态 emoji 显示不可行）：正常使用 = 大笑 😄，不行 = 黑脸 🌚；
- **电源语义**：关闭电源 → 黑屏；有电源 → 显示对应 emoji；
- **本期目标**：先验证能否根据不同的状态显示对应的 emoji。

### 1.2 可行性查证（Hermes 2026-08-20）

| 项 | 结论 | 证据 |
|---|---|---|
| 屏幕 + LVGL 链路 | ✅ 已验证可用 | `image_display` 示例（LVGL 9.5 + `bsp_display_start_with_config` + SPIFFS PNG + `bsp_display_backlight_on`）真机显示过；LVGL 自带 emoji 测试图 `F600.png`(😄)/`F617.png` |
| voice_agent.c 现状 | ⚠️ **零 LVGL 代码**（`grep lv_` = 0） | 纯语音固件，需集成屏幕初始化 |
| emoji 显示方式 | **PNG 图片 + `lv_img`**（LVGL montserrat 字体**不含 emoji 字形**，label 直写会变豆腐块） | font 目录无 emoji 字体 |
| 状态来源 | ✅ 现成 | WiFi：固件本地（多 WiFi 任务已有）；voicebridge：轮询 `GET /api/v1/health` 的 `tts.last_probe_ok`（服务端 05251ef 已就绪） |

### 1.3 实现方案（zcode 实施）

1. **屏幕初始化**：`bsp_i2c_init()` + `bsp_display_start_with_config()` + `bsp_display_backlight_on()` + LVGL 锁（照抄 image_display.c app_main 模式，LVGL 9.5 适配已在该示例验证）；
2. **emoji 资源**：4 个 emoji PNG（😄😵🤐🌚）放 SPIFFS（`S:/spiffs/`，image_display 已验证该链路）；PNG 来源：LVGL 自带 F600 可用作 😄，其余 3 个自备（转 PNG ≤ 200×200，SPIFFS 1MB 余量足够）；
3. **状态判定任务**（低优先级，每 30s 或状态变化触发）：
   - WiFi 正常 = 固件本地 got IP + 连接状态（复用多 WiFi 任务，不重复轮询）；
   - voicebridge 可用 = `GET /api/v1/health` 成功且 `tts.last_probe_ok == true`（超时 2s 判不可用）；
   - 4 态映射 → 切换 `lv_img_set_src` 显示对应 PNG；
   - **2 态退步**：仅「全正常 → 😄，否则 → 🌚」，同一套状态判定简化合并；
4. **电源语义**：断电自然黑屏（硬件行为，无需固件逻辑）；有电源即显示当前状态 emoji（开机显示 = 状态任务首次判定结果）。

### 1.4 待确认/验收

1. **4 态 vs 2 态**：先按 4 态实现；若真机显示/切换有问题，降 2 态（Vange 已授权退步）；
2. emoji PNG 素材由 zcode 准备（或 Hermes 协助下载，确认无版权问题用系统 emoji 转 PNG）；
3. 验收：真机看屏幕，依次模拟 4 种状态（断 WiFi / 停 voice-bridge / 两者都断）确认 emoji 正确切换；断电黑屏、上电显示。

## 需求 2：box3 联网搜索

### 2.1 现状（已查证）

| 环节 | 现状 |
|---|---|
| 路由 | `config.yaml` tool_keywords 含「查天气/搜索/搜网页/查快递」→ 命中走**慢路径 Hermes** |
| Hermes web 配置 | `~/.hermes/config.yaml`：`web.backend: tavily`、`search_backend: ''`（空）、`toolsets: [hermes-cli]` |
| voice-bridge 对接 | `llm.py` `HermesLLM.stream_chat` 用 httpx 直读 SSE，监听 `hermes.tool.progress` 事件判 `tool_seen`，只产出正文 |
| **历史卡点** | 2026-08-16 查证：Hermes API Server `/v1/chat/completions` 是纯聊天透传，**不执行 agent 工具循环**（传不传 tools 都直接编造）；后 llm.py 注释称「纯聊天透传是误判」，发现工具调用经 `hermes.tool.progress` SSE 事件暴露 |

> ⚠️ **核心待确认点**：Hermes 的工具循环（web 搜索）现在到底通不通？需要实测：让 voice-bridge 走慢路径问「今天广州天气」，看是否真触发 web 搜索并返回真实结果，还是仍走「查不了」诚实兜底。这是需求 2 的第一前置。

### 2.2 实现方案（分两条路，待实测后二选一）

**路线 A：走通 Hermes 工具循环（优先，改动最小）**
- 前提：Hermes API Server 实际能执行 web 工具（需实测验证 2.1 卡点）；
- 若通：只需确认 voice-bridge 慢路径能正确拿到「工具执行后的最终回答」，联网搜索即实现；
- 改动：基本零代码（可能只需微调 SYSTEM_PROMPT 让 Hermes 用 web 工具）。

**路线 B：voice-bridge 自己接搜索 API（兜底，Hermes 工具不通时）**
- 前提：Hermes 工具循环确实不通（回到 2026-08-16 查证结论）；
- 方案：voice-bridge 新增一个「搜索工具」——命中 tool_keywords 时，先调用搜索引擎 API（如 Tavily / 博查 / 火山），把搜索结果注入提示词，再走轻量通道 DeepSeek 生成回答（不依赖 Hermes 工具）；
- 需新增：搜索 API key 配置 + `app/search.py` 搜索模块 + pipeline 注入逻辑；
- 符合可插拔设计（搜索后端可换）。

### 2.3 待确认

1. **Hermes 工具循环是否可用**（第一前置，实测验证）；
2. 若走路线 B：搜索引擎选型（Tavily 需 key 付费？还是国内博查/火山等？需 Vange 定 + 提供 key）；
3. 搜索结果注入走轻量通道（快）还是慢路径（Hermes）？建议轻量通道（延迟低，搜索内容 + DeepSeek 生成）。

## 需求 3：BOX-3 记忆系统（Hermes 审查追加 2026-08-20）

### 3.1 需求原文

用户明确要求：「**box3 端的东西也必须纳入记忆系统**」——即通过语音告诉小V的长期信息（姓名、称呼、偏好、家庭成员等）必须被持久记住，跨会话、跨重启有效。

**触发背景（2026-08-20 实测）**：用户此前语音告诉小V「英文名 Vange」，次日问「还记得我叫什么名字吗」——小V忘了。

### 3.2 现状根因（已查证，llm.py）

| 环节 | 现状 | 问题 |
|---|---|---|
| 轻量通道（DeepSeek） | 每请求注入 `SYSTEM_PROMPT` + `USER.md`（只读） | USER.md 只含 Hermes 侧已知画像，**语音里新说的信息不在其中** |
| 会话历史 | 内存 deque，最近 8 条（4 轮）| **600s 无交互清空、服务重启即丢**，不落盘 |
| 慢路径 Hermes | 有 persistent memory + skills | 仅路由命中 HERMES 时才走；闲聊默认 lightweight，记忆不进 Hermes |

> 结论：语音对话中用户透露的信息**只活在内存窗口**（≤10 分钟），从未落盘——这是"英文名被忘"的根因。DeepSeek 裸模型本身无记忆能力。

### 3.3 实现方案（分层，voice-bridge 侧自主闭环）

**① 持久层：新增语音记忆文件 `voice-bridge/memory/user_facts.md`**

- 独立于 Hermes 的 USER.md（不写回 USER.md：Hermes memory 有字符上限 1375、且是 Hermes 侧管理的画像文件，voice-bridge 直接写会冲突/越权）；
- 格式与 USER.md 对齐（`§` 分隔条目），每条一行：`<时间> | <类别> | <事实>`，如 `2026-08-20 | identity | English name is Vange`；
- 条目去重：写入前按文本匹配已有条目，重复不追加；
- 上限：文件 ≤ 100 条 / 8KB，超限裁剪最旧条目（保留最近）；
- 本文件仅 voice-bridge 读写，可人工查看/编辑。

**② 提取层：每轮对话后自动「记忆提取」（全自动，无信号词门槛）**

- **触发语义（Vange 拍板 2026-08-20）**：与 Hermes 记忆模型一致——**默认自动记住**值得长期记住的信息，**不需要用户说「记住」**；只有当用户**明确说「别记/忘掉/不要记住」**时才删除对应记忆。原「信号词触发」（MEMORY_SIGNAL_WORDS）**废除**。
- 实现：路由为 lightweight 时，**每一轮**回复完成后后台异步调 DeepSeek 提取：
  - 输入：本轮 `user_text + assistant_text`；
  - 提示词：「从对话中提取值得长期记住的用户个人信息（姓名/称呼/偏好/家庭/身体/地址/物品等）。无则输出 `NONE`；有则输出 `REMEMBER: <类别>: <事实>`，每行一条，禁止编造。若用户明确要求遗忘某信息，输出 `FORGET: <关键词>`」；
  - 输出解析：`NONE` → 跳过；`REMEMBER:` 行 → 追加写 user_facts.md（去重后）；`FORGET:` 行 → 调 `memory.remove_by_keyword(关键词)` 删除；
- 放后台线程执行（不阻塞回复流，不加延迟）；失败静默重试 1 次，不抛错；
- **触发时机缺陷修正**：现实现将提取挂在 `stream_chat` 的流正常结束路径（llm.py:373-382），流异常中断（客户端断开/超时）会跳过提取——需改为 **pipeline 层在回复完成后统一触发**（try/finally 或独立于流），并覆盖 lightweight/hermes/rag 全部路由（hermes 慢路径 Hermes 自身有 persistent memory，可豁免或双写，zcode 定）。

**③ 注入层：system prompt 追加语音记忆**

- `LightweightLLM._system_prompt()`：在 USER.md 之后追加读取 `user_facts.md` 内容，前缀「以下是用户语音对话中透露的长期信息：」；
- USER.md 读取失败仍抛错降级（红线不变）；user_facts.md 缺失/为空 → 静默跳过（不影响启动）；
- 内存窗口（deque）保持不变：负责短期指代消解；user_facts.md 负责长期记忆，两者互补。

**④ 与 Hermes 记忆的同步（可选增强，不在本期）**

- 用户语音记忆先独立沉淀；需要进入 Hermes 主记忆（如给微信/其他 agent 共用）时，由 Hermes 侧定期/手动 review user_facts.md 并合并入 USER.md（Hermes memory 工具管理，voice-bridge 不越权写）；
- 本期不做自动双向同步，留 ISSUE 登记。

### 3.4 待确认

1. ~~提取触发方式：信号词 vs 每轮~~ **已拍板（Vange 2026-08-20）：每轮自动提取，无需信号词**；`FORGET` 遗忘指令随提取提示词一并实现。
2. 触发时机修正（pipeline 层统一触发）与 hermes 慢路径是否双写——zcode 实现时定。
3. user_facts.md 位置：`voice-bridge/memory/`（随项目入库，不含敏感值）即可，确认无异议。

## 四、验收标准（草案，Hermes 审查修订 2026-08-20）

### 需求 1
1. WiFi 断开时灯2 灭；WiFi 连上但服务端 TTS 不可用时灯2 灭；两者都正常时灯2 亮。
2. 灯1 保持麦克风开关状态语义不变。
3. 状态变化延迟 ≤ 轮询间隔（30s）+ 少量。

### 需求 2
1. 语音问「今天广州天气/最近的新闻」→ 返回**真实联网搜索结果**（非「查不了」、非编造）。
2. 非搜索类问题（闲聊/健康）不受影响，仍走原路由。
3. 搜索失败（无网络/key 失效）→ 诚实兜底「暂时查不了」，不编造。

### 需求 3（Hermes 审查追加，2026-08-20 修订）
1. 语音告诉小V「我的单车是 XX 型号」→ **无需说「记住」**，10 分钟后（内存窗口已过 TTL）再问「我的单车型号是什么」→ **答对**；
2. **重启 voice-bridge 后**仍答对（落盘验证，跨进程）；
3. 重复告诉同一信息 → 不重复积累（去重生效）；
4. 提取失败/服务异常 → 不影响本轮回复（异步、静默降级）；
5. 用户说「忘掉/别记我的单车型号」→ 该条目被删除，再问不再答出（FORGET 指令生效）；
6. 流异常中断（客户端断开）的对话**仍触发提取**（触发时机修正验收）。
